Spring MVC — REST API

Spring MVC maps incoming HTTP requests to Java methods. In Spring Boot 3.x, @RestController + @RequestMapping is the standard pattern. Every controller, error handler, SSE stream, and HTTP client in this project is built on Spring MVC.

@RestController
All four controllers use @RestController — StudentController, ResultController, AdminController, AuthController.
1 High Level Overview

@RestController = @Controller + @ResponseBody. Every method return value is serialised to JSON (via Jackson) and written directly to the HTTP response body. No view resolver, no template — just JSON. Combine with @RequestMapping at class level to set the base path for all methods.

2 Examples
Basic REST controllerSimple
@RestController
@RequestMapping("/api/students")
public class StudentController {

    private final StudentService studentService;

    public StudentController(StudentService studentService) {
        this.studentService = studentService;
    }

    @GetMapping("/{id}")
    public StudentDTO getStudent(@PathVariable Long id) {
        return studentService.getStudentById(id);  // returned as JSON automatically
    }
}

Request Mappings
Every endpoint uses a specific HTTP method annotation — GET for reads, POST for creates, PUT for full updates, PATCH for partial updates, DELETE for removes.
1 High Level Overview

Spring provides shorthand annotations for each HTTP verb: @GetMapping, @PostMapping, @PutMapping, @PatchMapping, @DeleteMapping. These are composites of @RequestMapping(method=...). You can narrow mappings by path, params, headers, or content type.

2 Examples
All HTTP verbsSimple
@GetMapping("/students")          // GET  /api/admin/students
@PostMapping("/students")         // POST /api/admin/students
@PutMapping("/students/{id}")     // PUT  /api/admin/students/1
@PatchMapping("/students/{id}")   // PATCH /api/admin/students/1
@DeleteMapping("/students/{id}")  // DELETE /api/admin/students/1
Full CRUD controllerMedium
@RestController
@RequestMapping("/api/admin/marks")
public class MarkController {

    private final ResultService resultService;
    public MarkController(ResultService resultService) {

    public MarkDTO createMark(@PathVariable Long studentId,

    @DeleteMapping("/{markId}")
    @ResponseStatus(HttpStatus.NO_CONTENT)

}
Method Parameters
@PathVariable for IDs in path, @RequestParam for filters/pagination, @RequestBody for JSON payloads, @AuthenticationPrincipal for the logged-in user.
1 High Level Overview

Spring MVC can inject many things into controller methods: path segments (@PathVariable), query params (@RequestParam), request body (@RequestBody), headers (@RequestHeader), the current authenticated user (@AuthenticationPrincipal), and Spring's Pageable for pagination — all resolved automatically.

2 Examples
All parameter typesSimple
// GET /api/students/42/marks?subject=MATHS&page=0&size=10
@GetMapping("/{studentId}/marks")
public Page<MarkDTO> getMarks(
        @PathVariable Long studentId,           // from URL path
        @RequestParam(required = false) String subject,  // ?subject=MATHS
        @RequestParam(defaultValue = "0") int page,
        @RequestParam(defaultValue = "10") int size) {
    return resultService.getMarks(studentId, subject, PageRequest.of(page, size));
}

// POST /api/admin/students  — JSON body mapped to record
@PostMapping("/students")
public ResponseEntity<StudentDTO> create(
        @Valid @RequestBody CreateStudentRequest request,
        @AuthenticationPrincipal UserDetails currentUser) {  // logged-in user
    var dto = studentService.createStudent(request, currentUser.getUsername());
    return ResponseEntity.status(HttpStatus.CREATED).body(dto);
}

// Spring auto-resolves Pageable from ?page=0&size=20&sort=name,asc
@GetMapping("/students")
public Page<StudentDTO> list(
        @RequestParam(required = false) String search,

ResponseEntity
Used on create endpoints (201 Created + Location header) and anywhere fine-grained HTTP status control is needed.
1 High Level Overview

ResponseEntity<T> gives you full control over the HTTP response: status code, headers, and body. For simple cases, use @ResponseStatus on the method. For anything needing dynamic status codes or custom headers (like Location after a create), use ResponseEntity.

2 Examples
201 Created with Location headerSimple
@PostMapping("/students")
public ResponseEntity<StudentDTO> createStudent(
        @Valid @RequestBody CreateStudentRequest request) {
    StudentDTO created = studentService.createStudent(request);
    URI location = URI.create("/api/admin/students/" + created.id());
    return ResponseEntity.created(location).body(created);
    // HTTP 201 Created
    // Location: /api/admin/students/42
    // Body: { "id": 42, "name": "...", ... }
}
Conditional response — 200 or 404Medium
@GetMapping("/students/{id}")
public ResponseEntity<StudentDTO> getStudent(@PathVariable Long id) {
    return studentService.findById(id)
        .map(dto -> ResponseEntity.ok(dto))          // 200 OK + body
        .orElse(ResponseEntity.notFound().build());   // 404 No body
}
@RestControllerAdvice — Global Exception Handler
GlobalExceptionHandler catches StudentNotFoundException, validation errors, and all unhandled exceptions — returns ProblemDetail for every error.
1 High Level Overview

@RestControllerAdvice is a global exception handler that applies to all controllers. Methods annotated with @ExceptionHandler catch specific exceptions thrown anywhere in the controller layer. Spring Boot 3.x pairs this with ProblemDetail (RFC 7807) for a standardised error response format.

2 Examples
Catch specific exceptionSimple
@RestControllerAdvice
public class GlobalExceptionHandler {

    @ExceptionHandler(StudentNotFoundException.class)
    @ResponseStatus(HttpStatus.NOT_FOUND)
    public ProblemDetail handleNotFound(StudentNotFoundException ex) {
        var problem = ProblemDetail.forStatusAndDetail(HttpStatus.NOT_FOUND, ex.getMessage());
        problem.setTitle("Student Not Found");
        return problem;
    }
}
Full exception handlerReal-time
@RestControllerAdvice
public class GlobalExceptionHandler {

    // 404 — business entity not found
    @ExceptionHandler(StudentNotFoundException.class)
    public ProblemDetail handleNotFound(StudentNotFoundException ex) {
        var p = ProblemDetail.forStatusAndDetail(HttpStatus.NOT_FOUND, ex.getMessage());
        p.setTitle("Student Not Found");
        return p;
    }

    // 400 — @Valid failed on @RequestBody
    @ExceptionHandler(MethodArgumentNotValidException.class)
    public ProblemDetail handleValidation(MethodArgumentNotValidException ex) {
        var p = ProblemDetail.forStatus(HttpStatus.BAD_REQUEST);
        p.setTitle("Validation Failed");
        Map<String, String> errors = new LinkedHashMap<>();
        ex.getBindingResult().getFieldErrors()
            .forEach(e -> errors.put(e.getField(), e.getDefaultMessage()));
        p.setProperty("errors", errors);
        return p;
    }

    // 403 — method security @PreAuthorize failed
    @ExceptionHandler(AccessDeniedException.class)
    public ProblemDetail handleForbidden(AccessDeniedException ex) {
        var p = ProblemDetail.forStatusAndDetail(HttpStatus.FORBIDDEN, "Access denied");
        p.setTitle("Forbidden");
        return p;
    }

    // 409 — optimistic locking conflict
    @ExceptionHandler(ObjectOptimisticLockingFailureException.class)
    public ProblemDetail handleConflict(ObjectOptimisticLockingFailureException ex) {
        var p = ProblemDetail.forStatusAndDetail(HttpStatus.CONFLICT,
            "Record was modified by another user. Please refresh and try again.");
        p.setTitle("Conflict");
        return p;
    }

    // 500 — everything else
    @ExceptionHandler(Exception.class)
    public ProblemDetail handleAll(Exception ex) {
        var p = ProblemDetail.forStatusAndDetail(
            HttpStatus.INTERNAL_SERVER_ERROR, "An unexpected error occurred");
        p.setTitle("Internal Server Error");
        return p;
    }
}
ProblemDetail (RFC 7807)
All error responses in this project use ProblemDetail — standardised JSON structure with type, title, status, detail, and custom properties.
1 High Level Overview

RFC 7807 defines a standard JSON error format for APIs. Spring Boot 3.0 introduced ProblemDetail as a first-class return type. Instead of custom error POJOs, every error response now looks the same: type, title, status, detail, instance. You can add custom properties with setProperty().

2 Examples
ProblemDetail responseSimple
// What the client receives for a 404:
// {
//   "type": "about:blank",
//   "title": "Student Not Found",
//   "status": 404,
//   "detail": "Student with id 99 does not exist",
//   "instance": "/api/admin/students/99"
// }

ProblemDetail p = ProblemDetail.forStatusAndDetail(
    HttpStatus.NOT_FOUND, "Student with id 99 does not exist");
p.setTitle("Student Not Found");
p.setProperty("studentId", 99);   // add any extra fields
Validation error with field detailsMedium
// 400 validation response:
// {
//   "title": "Validation Failed",
//   "status": 400,
//   "errors": {
//     "name": "must not be blank",
//     "score": "must be between 0 and 100"
//   }
// }
var p = ProblemDetail.forStatus(HttpStatus.BAD_REQUEST);
p.setTitle("Validation Failed");
p.setProperty("errors", Map.of(

SseEmitter — Server-Sent Events
Used at GET /api/results/stream — pushes "marks published" events to the student's browser in real time, which the frontend shows as a toast notification.
1 High Level Overview

Server-Sent Events (SSE) is a one-way push channel from server to client over a long-lived HTTP connection. SseEmitter holds the connection open; you call emitter.send() to push events. The browser's EventSource API reconnects automatically. Lighter than WebSockets for one-way notification use cases.

2 Examples
Basic SSE endpointSimple
@GetMapping(value = "/stream", produces = MediaType.TEXT_EVENT_STREAM_VALUE)
public SseEmitter stream() {
    SseEmitter emitter = new SseEmitter(Long.MAX_VALUE); // keep alive forever
    // Store emitter and send events when marks are published
    notificationService.register(emitter);
    emitter.onCompletion(() -> notificationService.remove(emitter));
    emitter.onTimeout(()    -> notificationService.remove(emitter));
    return emitter;
}
Full SSE with student-scoped emittersReal-time
@RestController
@RequestMapping("/api/results")
public class ResultController {

    private final NotificationService notificationService;

    @GetMapping(value = "/stream", produces = MediaType.TEXT_EVENT_STREAM_VALUE)
    @PreAuthorize("hasRole('STUDENT')")
    public SseEmitter stream(@AuthenticationPrincipal UserDetails user) {
        return notificationService.createEmitter(user.getUsername());
    }
}

// In NotificationService:
private final ConcurrentHashMap<String, SseEmitter> emitters = new ConcurrentHashMap<>();

public SseEmitter createEmitter(String username) {
    var emitter = new SseEmitter(Duration.ofMinutes(30).toMillis());
    emitters.put(username, emitter);
    emitter.onCompletion(() -> emitters.remove(username));
    emitter.onTimeout(()    -> emitters.remove(username));
    return emitter;
}

// Called when admin publishes marks
@TransactionalEventListener(phase = TransactionPhase.AFTER_COMMIT)
public void onMarksUpdated(MarksUpdatedEvent event) {
    var emitter = emitters.get(event.getStudentUsername());
    if (emitter != null) {
        try {
            emitter.send(SseEmitter.event()
                .name("marks-published")
                .data(Map.of("message", "Your results have been updated!")));
        } catch (IOException e) {
            emitters.remove(event.getStudentUsername());
        }
    }
}
Pagination — PageRequest & Pageable
Admin student list uses Pageable — GET /api/admin/students?page=0&size=20&sort=name,asc returns a Page with content + total count.
1 High Level Overview

Pageable is Spring Data's abstraction for page number, page size, and sorting. Spring MVC resolves it automatically from query parameters. Repository methods returning Page<T> run two queries: one for the data, one for the total count. The response includes content, totalElements, totalPages, number, and size.

2 Examples
Pageable in controller + repositoryMedium
// Controller — Spring resolves Pageable from ?page=0&size=20&sort=name,asc
@GetMapping("/students")
public Page<StudentDTO> list(Pageable pageable) {
    return studentService.getAllStudents(pageable);
}

// Service
public Page<StudentDTO> getAllStudents(Pageable pageable) {
    return studentRepository.findAll(pageable)
        .map(s -> new StudentDTO(s.getId(), s.getName(),
                                  s.getRollNumber(), s.getEmail()));
}

// Response JSON:
// {
//   "content": [ { "id": 1, "name": "Arjun"... }, ... ],
//   "totalElements": 150,
//   "totalPages": 8,
//   "number": 0,
//   "size": 20
// }

HTTP Interface Client (@HttpExchange)
GradeImportClient uses @HttpExchange to call an external grade import API — declarative, like Spring Data repositories but for HTTP calls.
1 High Level Overview

Spring 6 / Boot 3.x introduced declarative HTTP clients using @HttpExchange. Define an interface, annotate methods with @GetExchange, @PostExchange etc., and Spring generates the implementation. Backed by RestClient (Boot 3.2+) or WebClient. Replaces boilerplate RestTemplate calls.

2 Examples
Declare and use an HTTP client interfaceMedium
// 1. Define the interface
@HttpExchange(url = "/api/grades", accept = "application/json")
public interface GradeImportClient {

    @GetExchange("/students/{rollNumber}")
    ExternalGradeDTO getGradeForStudent(@PathVariable String rollNumber);

    @PostExchange("/bulk-import")
    List<ExternalGradeDTO> importGrades(@RequestBody List<String> rollNumbers);
}

// 2. Register it as a bean in @Configuration
@Bean
public GradeImportClient gradeImportClient() {
    var restClient = RestClient.builder()
        .baseUrl("https://external-grades.example.com")
        .defaultHeader("X-API-Key", appProperties.externalApiKey())
        .build();
    return HttpServiceProxyFactory
        .builderFor(RestClientAdapter.create(restClient))
        .build()
        .createClient(GradeImportClient.class);
}

// 3. Inject and use like any other Spring bean
@Service
public class GradeImportService {
    private final GradeImportClient client;
    public GradeImportService(GradeImportClient client) { this.client = client; }

    public void importForStudent(String rollNumber) {
        var grade = client.getGradeForStudent(rollNumber);
        // process grade...
    }
}
CORS
CORS is configured globally in SecurityConfig to allow the Next.js frontend (localhost:3000 in dev, production domain in prod) to call the API.
1 High Level Overview

Browsers block cross-origin requests by default. When the Next.js frontend (port 3000) calls the Spring API (port 8080), the browser first sends a preflight OPTIONS request. Spring's CORS support handles this. Configure globally via CorsConfigurationSource in the security filter chain — this takes precedence over @CrossOrigin on controllers.

3 In This Project
config/SecurityConfig.java — CORS configuration
@Bean
public SecurityFilterChain filterChain(HttpSecurity http) throws Exception {
    http.cors(cors -> cors.configurationSource(corsConfigurationSource()))
        // ... rest of security config
    return http.build();
}

@Bean
public CorsConfigurationSource corsConfigurationSource() {
    var config = new CorsConfiguration();
    config.setAllowedOrigins(List.of(
        "http://localhost:3000",           // Next.js dev
        "https://student-portal.example.com" // production
    ));
    config.setAllowedMethods(List.of("GET", "POST", "PUT", "PATCH", "DELETE", "OPTIONS"));
    config.setAllowedHeaders(List.of("*"));
    config.setAllowCredentials(true);   // allow cookies / Authorization header
    config.setMaxAge(3600L);            // preflight cache 1 hour

    var source = new UrlBasedCorsConfigurationSource();
    source.registerCorsConfiguration("/api/**", config);
    return source;
}
