Configuration Properties

Instead of scattering @Value("${...}") annotations across 20 classes, this project uses a single AppProperties record that maps the entire app.* config namespace. Typed, validated, IDE-completable, and testable by just constructing a record.

@ConfigurationProperties
AppProperties maps the entire app.* namespace — JWT secret, email config, storage config. Injected wherever needed via constructor injection like any other bean.
1 High Level Overview

@ConfigurationProperties(prefix = "app") binds all YAML/properties keys under app.* to the annotated class. Spring Boot uses relaxed binding: app.jwt-secret, app.jwtSecret, and APP_JWT_SECRET (env var) all map to the same field. Benefits over @Value: type safety, IDE autocompletion, grouped validation, and easy testing.

2 Examples
@Value vs @ConfigurationPropertiesSimple
// ❌ @Value — scattered, no type safety, hard to test
@Service
public class JwtService {
    @Value("${app.jwt-secret}")             private String jwtSecret;
    @Value("${app.jwt-expiration-minutes}") private int    expirationMinutes;
}
@Service
public class EmailService {
    @Value("${app.email.host}") private String host;
    @Value("${app.email.port}") private int    port;
    @Value("${app.email.from}") private String from;
}

// ✅ @ConfigurationProperties — one place, typed, injected
@Service
public class JwtService {
    private final AppProperties props;
    public JwtService(AppProperties props) { this.props = props; }
    // Use: props.jwtSecret(), props.jwtExpirationMinutes()
}
@Service
public class EmailService {
    private final AppProperties props;
    public EmailService(AppProperties props) { this.props = props; }
    // Use: props.email().host(), props.email().port()
}
Enable in configurationMedium
// Option A — on the record itself (Boot 3.x preferred)
@ConfigurationProperties(prefix = "app")
@Validated
public record AppProperties(...) {}

// Then enable via:
@SpringBootApplication
@EnableConfigurationProperties(AppProperties.class)
public class StudentPortalApplication { ... }

// Option B — @ConfigurationPropertiesScan (scans the package)
@SpringBootApplication
@ConfigurationPropertiesScan("com.studentresults.properties")
public class StudentPortalApplication { ... }
Properties as a Java Record
AppProperties is a record — immutable config, no boilerplate setters, IDE-completable via spring-boot-configuration-processor on the classpath.
1 High Level Overview

Spring Boot 3.x supports @ConfigurationProperties on Java records via constructor binding. Records are ideal: immutable (config shouldn't change at runtime), compact (no getters/setters), naturally support nested records for sub-config groups, and work with @Validated for startup-time validation.

3 In This Project
properties/AppProperties.java
@ConfigurationProperties(prefix = "app")
@Validated
public record AppProperties(

    @NotBlank
    String jwtSecret,

    @Min(1) @Max(1440)
    int jwtExpirationMinutes,

    boolean cacheEnabled,

    Email   email,    // nested record — maps app.email.*
    Storage storage,  // nested record — maps app.storage.*
    Digest  digest    // nested record — maps app.digest.*

) {
    public record Email(
        @NotBlank String host,
        @Min(1) @Max(65535) int port,
        @NotBlank String from,
        String username,
        String password
    ) {}

    public record Storage(
        @NotBlank String bucket,
        @NotBlank String region
    ) {}

    public record Digest(
        @NotBlank String cron,
        boolean enabled
    ) {}
}
@Validated on Properties
If JWT_SECRET env var is missing, the app fails at startup with a clear error — not silently at runtime when the first login request tries to sign a JWT.
1 High Level Overview

@Validated on a @ConfigurationProperties class runs Bean Validation when the app starts. If any constraint fails — missing required env var, port out of range — Spring Boot refuses to start and prints the exact property that failed. Catch config mistakes at deploy time, not at runtime.

Nested Records + application.yml
The YAML hierarchy mirrors the nested record structure exactly — app.email.host maps to AppProperties.email().host().
3 In This Project
src/main/resources/application.yml
// application.yml (shown as Java comments for syntax highlighting)
// app:
//   jwt-secret: ${JWT_SECRET}              -> AppProperties.jwtSecret()
//   jwt-expiration-minutes: 60             -> AppProperties.jwtExpirationMinutes()
//   cache-enabled: true                    -> AppProperties.cacheEnabled()
//
//   email:                                 -> AppProperties.email()
//     host: smtp.sendgrid.net              -> AppProperties.Email.host()
//     port: 587                            -> AppProperties.Email.port()
//     from: results@school.com             -> AppProperties.Email.from()
//     username: ${SENDGRID_USERNAME}
//     password: ${SENDGRID_PASSWORD}
//
//   storage:                               -> AppProperties.storage()
//     bucket: student-results-bucket       -> AppProperties.Storage.bucket()
//     region: ap-south-1                   -> AppProperties.Storage.region()
//
//   digest:                                -> AppProperties.digest()
//     cron: "0 0 7 * * MON-FRI"           -> AppProperties.Digest.cron()
//     enabled: true                        -> AppProperties.Digest.enabled()

// Usage in JwtService — clean, typed, no @Value
@Service
public class JwtService {
    private final AppProperties appProperties;

    public JwtService(AppProperties appProperties) {
        this.appProperties = appProperties;
    }

    public String generateToken(UserDetails user) {
        return Jwts.builder()
            .subject(user.getUsername())
            .expiration(new Date(System.currentTimeMillis()
                + appProperties.jwtExpirationMinutes() * 60_000L))
            .signWith(Keys.hmacShaKeyFor(
                Decoders.BASE64.decode(appProperties.jwtSecret())))
            .compact();
    }
}
Profile-Specific YAML
application-dev.yml enables Docker Compose and verbose SQL. application-prod.yml enables structured JSON logging, disables SQL echo, and tunes the connection pool.
1 High Level Overview

Spring Boot merges application.yml (base) with application-{profile}.yml (override). Profile-specific files override only the keys they define — the rest comes from base. Activate a profile with SPRING_PROFILES_ACTIVE=prod env var or --spring.profiles.active=dev JVM arg.

Environment Secrets
JWT_SECRET, DB_PASSWORD, SENDGRID_PASSWORD are never in source code. application.yml references them as ${ENV_VAR} — Spring substitutes at startup from the OS environment.
1 High Level Overview

Spring Boot's ${VAR_NAME} syntax reads from system environment variables, JVM system properties (-Dvar=val), or .env files (with Spring Boot 3.x dotenv support). For Docker/Kubernetes, pass secrets as environment variables. Never commit secrets to Git — use ${VAR} references and set the real values in CI/CD or a secrets manager.
