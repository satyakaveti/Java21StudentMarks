Spring Scheduling

Spring's @Scheduled annotation turns any Spring bean method into a background job. This project uses three scheduled tasks: a daily digest email to students at 7AM on weekdays, a 60-second JWT blacklist cleanup, and a 5-minute subject cache refresh.

@EnableScheduling
Placed on a @Configuration class — activates the background scheduler thread pool that runs all @Scheduled methods.
1 High Level Overview

Without @EnableScheduling, all @Scheduled annotations are silently ignored. Place it on any @Configuration class. Spring creates a scheduled thread pool executor. Combined with spring.threads.virtual.enabled=true (Boot 3.2+), scheduled tasks run on virtual threads.

3 In This Project
config/AsyncConfig.java (or any @Configuration)
@Configuration
@EnableAsync
@EnableScheduling   // ← activates all @Scheduled methods
public class AsyncConfig {

    @Bean(name = "virtualThreadExecutor")
    public Executor virtualThreadExecutor() {
        return Executors.newVirtualThreadPerTaskExecutor();
    }
}

@Scheduled(cron = "...")
Used for the daily digest email — runs at exactly 7AM Monday to Friday. Cron gives precise calendar-based scheduling.
1 High Level Overview

Spring cron format has 6 fields: second minute hour day-of-month month day-of-week. Supports standard cron operators: * (every), ? (any), - (range), , (list), / (step). Spring also supports macros: @yearly, @monthly, @weekly, @daily, @hourly.

2 Examples
Common cron expressionsSimple
// Format: "second minute hour day month weekday"

@Scheduled(cron = "0 0 7 * * MON-FRI")   // 7:00 AM weekdays
@Scheduled(cron = "0 0 0 * * *")          // midnight every day
@Scheduled(cron = "0 0 * * * *")          // top of every hour
@Scheduled(cron = "0 */30 * * * *")       // every 30 minutes
@Scheduled(cron = "0 0 8 1 * *")          // 8AM on 1st of every month

// From properties file — easier to change per environment
@Scheduled(cron = "${app.digest.cron:0 0 7 * * MON-FRI}")
public void dailyDigest() { ... }
Cron with timezoneMedium
// Run at 7AM IST (Indian Standard Time) regardless of server timezone
@Scheduled(cron = "0 0 7 * * MON-FRI", zone = "Asia/Kolkata")
public void dailyDigestIST() {
    digestService.sendDailyEmails();
}
@Scheduled(fixedDelay = ...)
JWT blacklist cleanup uses fixedDelay — waits 60 seconds after the previous run completes before starting the next. Prevents overlap if cleanup takes longer than expected.
1 High Level Overview

fixedDelay waits N milliseconds after the previous execution completes before starting again. Use this when you want to ensure runs don't overlap — the gap between runs is always at least N ms. Pair with initialDelay to skip the first run on startup.

2 Examples
fixedDelay vs fixedRateSimple
// fixedDelay — gap of 60s AFTER previous run finishes
// Run1 starts 0s, finishes 5s → Run2 starts at 65s
@Scheduled(fixedDelay = 60_000)
public void cleanupJwtBlacklist() { ... }

// fixedRate — starts every 60s regardless of how long previous run took
// Run1 starts 0s (takes 70s) → Run2 starts 60s (overlap!)
@Scheduled(fixedRate = 60_000)
public void pollExternalApi() { ... }
// For fixedRate, use fixedRate + @Async if overlap is a concern
With initialDelayMedium
// Wait 30 seconds after app starts before first run, then every 60 seconds
@Scheduled(fixedDelay = 60_000, initialDelay = 30_000)
public void cleanupJwtBlacklist() {
    var cutoff = Instant.now().minus(Duration.ofHours(24));
    jwtBlacklistRepository.deleteExpiredBefore(cutoff);
    log.debug("[SCHEDULER] JWT blacklist cleaned up");
}
@Scheduled(fixedRate = ...)
Subject cache refresh uses fixedRate — fires every 5 minutes on a fixed schedule regardless of when the previous refresh completed.
1 High Level Overview

fixedRate starts execution every N milliseconds from the previous start time. If execution takes longer than N ms, subsequent executions may queue up (run back-to-back to catch up). Best for lightweight tasks where predictable intervals matter more than preventing overlap.

3 In This Project
scheduler/CacheRefreshScheduler.java
@Component
@Profile("!test")   // don't run scheduled tasks during tests
public class CacheRefreshScheduler {

    private final CacheManager cacheManager;
    private final SubjectRepository subjectRepository;

    public CacheRefreshScheduler(CacheManager cacheManager,
                                  SubjectRepository subjectRepository) {
        this.cacheManager = cacheManager;
        this.subjectRepository = subjectRepository;
    }

    // Refresh subject config cache every 5 minutes
    @Scheduled(fixedRate = 300_000)
    public void refreshSubjectsCache() {
        var cache = cacheManager.getCache("subjects");
        if (cache != null) {
            cache.clear();
            // Re-warm the cache
            subjectRepository.findAll()
                .forEach(s -> cache.put(s.getId(), s.getName()));
        }
        log.debug("[SCHEDULER] Subjects cache refreshed");
    }
}
Daily Digest Email
At 7AM Mon-Fri, sends every student a summary of their latest marks if they have pending unread results.
3 In This Project
scheduler/DigestScheduler.java
@Component
@Profile("!test")
public class DigestScheduler {

    private static final Logger log = LoggerFactory.getLogger(DigestScheduler.class);
    private final StudentRepository studentRepository;
    private final ResultService resultService;
    private final EmailClient emailClient;

    public DigestScheduler(StudentRepository studentRepository,
                            ResultService resultService,
                            EmailClient emailClient) {
        this.studentRepository = studentRepository;
        this.resultService = resultService;
        this.emailClient = emailClient;
    }

    @Scheduled(cron = "0 0 7 * * MON-FRI", zone = "Asia/Kolkata")
    public void sendDailyDigest() {
        log.info("[DIGEST] Starting daily result digest...");

        // Java 21 virtual thread executor handles the fan-out
        var students = studentRepository.findAllActive();
        int sent = 0;

        for (var student : students) {
            var summary = resultService.getSummaryForStudent(student.getId());
            if (summary.hasUnreadResults()) {
                emailClient.send(
                    student.getEmail(),
                    "Your Daily Results Summary — " + LocalDate.now(),
                    buildDigestBody(student.getName(), summary));
                sent++;
            }
        }
        log.info("[DIGEST] Sent {} digest emails", sent);
    }

    private String buildDigestBody(String name, ResultSummaryDTO summary) {
        return """
            Hi %s,
            Here's your results summary:
            • Maths:   %d (%s)
            • Science: %d (%s)
            • English: %d (%s)
            Total: %d | Average: %.1f
            """.formatted(name,
                summary.mathsScore(),    summary.mathsGrade(),
                summary.scienceScore(),  summary.scienceGrade(),
                summary.englishScore(),  summary.englishGrade(),
                summary.totalScore(),    summary.average());
    }
}
JWT Blacklist Cleanup
When a user logs out, their JWT is added to a blacklist table. This scheduler removes expired entries every 60 seconds to keep the table small.
3 In This Project
scheduler/DigestScheduler.java — JWT cleanup
// In DigestScheduler or a dedicated SecurityScheduler
@Scheduled(fixedDelay = 60_000, initialDelay = 60_000)
public void cleanExpiredTokens() {
    // Delete JWT blacklist entries older than 24 hours
    var cutoff = LocalDateTime.now().minusHours(24);
    int deleted = jwtBlacklistRepository.deleteByCreatedAtBefore(cutoff);
    if (deleted > 0) {
        log.debug("[SCHEDULER] Removed {} expired JWT blacklist entries", deleted);
    }
}
