Virtual Threads & RestClient

Two major Spring Boot 3.2 + Java 21 features: Virtual Threads let Tomcat handle thousands of concurrent requests without a large thread pool — one line of config. RestClient replaces the old RestTemplate with a clean fluent API and native support for the @HttpExchange declarative client.

Virtual Threads (Java 21 — JEP 444)
With spring.threads.virtual.enabled=true, every Tomcat request thread, every @Async task, and every scheduled job runs on a Java 21 virtual thread — not a platform thread.
1 High Level Overview

Traditional Java web servers use a platform thread per request — expensive (1MB stack) and limited (~200-500 threads practical max). Virtual threads are JVM-managed lightweight threads (a few hundred bytes) that can be created in millions. When a virtual thread blocks on I/O (DB query, HTTP call), the JVM parks it and runs another virtual thread on the OS thread — zero cost blocking.

2 Examples
Platform thread problem — 500 concurrent requests saturate poolSimple
// Traditional Tomcat — default 200 threads
// Each request: handler picks up a thread, calls DB (blocks 20ms), returns thread
// At 500 concurrent requests: 300 requests queue, waiting for a free thread
// Result: slow response, thread starvation, high latency under load

// With Virtual Threads:
// Each request gets its own virtual thread (costs ~200 bytes)
// Thread blocks on DB → JVM parks virtual thread, OS thread handles another request
// 10,000 concurrent requests? No problem — each gets a virtual thread
Create virtual threads manually (for understanding)Medium
// Old platform thread
Thread platform = new Thread(() -> System.out.println("platform"));
platform.start(); // 1MB stack allocated

// Java 21 virtual thread — lightweight
Thread virtual = Thread.ofVirtual()
    .name("vt-worker")
    .start(() -> System.out.println("virtual"));  // ~200 bytes

// Virtual thread executor — one per task
ExecutorService executor = Executors.newVirtualThreadPerTaskExecutor();
executor.submit(() -> {
    // This blocks — but it's OK, virtual thread is parked, not wasting an OS thread
    var result = restClient.get().uri("/api/data").retrieve().body(String.class);
    System.out.println(result);
});
Fetch all 3 subjects in parallel with virtual threadsReal-time
// Java 21 — structured concurrency (JEP 453 — preview)
// Fetch Maths, Science, English marks in parallel, join all results
public ResultSummaryDTO getFullSummary(Long studentId) throws Exception {
    try (var scope = new StructuredTaskScope.ShutdownOnFailure()) {

        // Fork 3 tasks — each runs on its own virtual thread
        var mathsFuture   = scope.fork(() -> markRepo.findByStudentAndSubject(studentId, "MATHS"));
        var scienceFuture = scope.fork(() -> markRepo.findByStudentAndSubject(studentId, "SCIENCE"));
        var englishFuture = scope.fork(() -> markRepo.findByStudentAndSubject(studentId, "ENGLISH"));

        scope.join();           // wait for all three
        scope.throwIfFailed();  // if any threw, propagate

        // All three completed successfully — collect results
        return new ResultSummaryDTO(
            mathsFuture.get(),
            scienceFuture.get(),
            englishFuture.get()
        );
        // Total time = max(maths, science, english) — not sum!
    }
}
Spring Boot Virtual Thread Config
One property enables virtual threads for Tomcat request handling, all @Async tasks, and all scheduled jobs — no code changes needed.
1 High Level Overview

Spring Boot 3.2 added first-class virtual thread support. Set spring.threads.virtual.enabled=true and Spring Boot automatically configures Tomcat to use virtual threads for request handling, and Spring's AsyncTaskExecutor to use virtual threads for @Async methods. Zero code changes required.

application.yml · config/AsyncConfig.java
// application.yml — one line enables virtual threads everywhere
// spring:
//   threads:
//     virtual:
//       enabled: true   # Tomcat + @Async + @Scheduled all use virtual threads

// What this does under the hood (Spring Boot does this for you):
// 1. TomcatProtocolHandlerCustomizer sets Tomcat's executor to virtual thread executor
// 2. SimpleAsyncTaskExecutorBuilder sets @Async executor to virtual thread executor
// 3. ScheduledTaskExecutor uses virtual threads for @Scheduled

// AsyncConfig.java — still useful for naming and custom configuration
@Configuration
@EnableAsync
public class AsyncConfig {

    @Bean(name = "virtualThreadExecutor")
    public Executor virtualThreadExecutor() {
        // Named executor for @Async("virtualThreadExecutor")
        // Thread names prefixed for easier debugging
        var factory = Thread.ofVirtual()
            .name("student-portal-vt-", 0)
            .factory();
        return Executors.newThreadPerTaskExecutor(factory);
    }
}

// All @Async methods now run on virtual threads:
@Async("virtualThreadExecutor")
@TransactionalEventListener(phase = TransactionPhase.AFTER_COMMIT)
public void onMarksUpdated(MarksUpdatedEvent event) {
    emailClient.send(...);  // blocking I/O — fine on virtual thread
}
Structured Concurrency (Java 21 Preview — JEP 453)
Used to fetch Maths, Science, English marks in parallel — all three run concurrently, total time = longest query, not sum of all three.
1 High Level Overview

Structured Concurrency treats a group of concurrent tasks as a single unit of work. StructuredTaskScope opens a scope; you fork() subtasks; join() waits for all to complete. ShutdownOnFailure: if any task fails, cancel the rest. ShutdownOnSuccess: as soon as one task succeeds, cancel the rest. Structured — the scope closes only when all forks complete.

3 In This Project
service/ResultService.java — parallel subject fetch
@Transactional(readOnly = true)
public ResultSummaryDTO getFullSummary(Long studentId) {
    try (var scope = new StructuredTaskScope.ShutdownOnFailure()) {

        // Fork all three — run concurrently on virtual threads
        var mathsFork   = scope.fork(() ->
            markRepository.findByStudentAndSubjectName(studentId, "MATHS"));
        var scienceFork = scope.fork(() ->
            markRepository.findByStudentAndSubjectName(studentId, "SCIENCE"));
        var englishFork = scope.fork(() ->
            markRepository.findByStudentAndSubjectName(studentId, "ENGLISH"));

        // Wait for all three to finish (or any to fail)
        scope.join();
        scope.throwIfFailed();  // throws if any fork threw an exception

        // Collect results
        return buildSummary(
            mathsFork.get(),
            scienceFork.get(),
            englishFork.get()
        );
        // Performance: 3 x 20ms DB queries → ~20ms total (not 60ms)

    } catch (InterruptedException e) {
        Thread.currentThread().interrupt();
        throw new ServiceException("Summary fetch interrupted", e);
    } catch (ExecutionException e) {
        throw new ServiceException("Summary fetch failed", e.getCause());
    }
}
Scoped Values (Java 21 Preview — JEP 446)
ScopedValue<UserContext> passes the authenticated user through the call stack without ThreadLocal — safe across virtual threads where ThreadLocal inheritance is unpredictable.
1 High Level Overview

Virtual threads make ThreadLocal problematic — a virtual thread may run on different OS threads during its lifetime and inherit from wrong parents. ScopedValue (Java 21 preview) is the replacement: an immutable, stack-bound value available to the current call tree, including child virtual threads. Set once with ScopedValue.where().run(), read anywhere in the call tree with .get().

3 In This Project
security/UserContext.java · JwtAuthFilter.java
// Define the scoped value — a static final holder
public class UserContext {
    // The ScopedValue holds the authenticated user for the current request scope
    public static final ScopedValue<AuthenticatedUser> CURRENT_USER =
        ScopedValue.newInstance();
}

// In JwtAuthFilter — set the scoped value for this request's call tree
@Override
protected void doFilterInternal(HttpServletRequest req,
                                 HttpServletResponse res,
                                 FilterChain chain)
        throws ServletException, IOException {

    var jwt = extractToken(req);
    if (jwt != null && jwtService.isValid(jwt)) {
        var user = new AuthenticatedUser(
            jwtService.extractId(jwt),
            jwtService.extractUsername(jwt),
            jwtService.extractRoles(jwt));

        // Bind user to this request's scope — available throughout call tree
        ScopedValue.where(UserContext.CURRENT_USER, user)
            .run(() -> {
                try { chain.doFilter(req, res); }
                catch (Exception e) { throw new RuntimeException(e); }
            });
    } else {
        chain.doFilter(req, res);
    }
}

// In AuditAspect — read without passing as parameter
@Around("@annotation(Auditable)")
public Object audit(ProceedingJoinPoint pjp, Auditable a) throws Throwable {
    var user = UserContext.CURRENT_USER.isBound()
        ? UserContext.CURRENT_USER.get().username()
        : "anonymous";
    // No need to pass user through method parameters!
    auditLog.record(a.action(), user, pjp.getSignature().getName());
    return pjp.proceed();
}
RestClient (Spring Boot 3.2)
Replaces RestTemplate for the external grade import API call — synchronous, fluent API, works naturally with virtual threads.
1 High Level Overview

Spring Boot 3.2 introduced RestClient — a synchronous HTTP client with a fluent API (like WebClient but blocking). It replaces the aging RestTemplate. Key features: fluent builder pattern, automatic JSON binding via Jackson, error handling with onStatus(), and timeout configuration. With virtual threads, synchronous blocking calls are fine — no need for reactive WebClient.

3 In This Project
config/HttpClientConfig.java · service/GradeImportService.java
// Bean configuration
@Configuration
public class HttpClientConfig {

    private final AppProperties appProperties;

    public HttpClientConfig(AppProperties appProperties) {
        this.appProperties = appProperties;
    }

    @Bean
    public RestClient gradeImportRestClient() {
        return RestClient.builder()
            .baseUrl("https://external-grades.example.com")
            .defaultHeader("X-API-Key", appProperties.externalApiKey())
            .defaultHeader("Accept", "application/json")
            .requestInterceptor((req, body, execution) -> {
                // Log every outgoing request
                log.debug("HTTP {} {}", req.getMethod(), req.getURI());
                return execution.execute(req, body);
            })
            .build();
    }
}

// Service — fluent, readable, synchronous
@Service
public class GradeImportService {

    private final RestClient restClient;

    public GradeImportService(RestClient gradeImportRestClient) {
        this.restClient = gradeImportRestClient;
    }

    public ExternalGradeDTO getExternalGrade(String rollNumber) {
        return restClient.get()
            .uri("/students/{rollNumber}/grade", rollNumber)
            .retrieve()
            .onStatus(HttpStatusCode::is4xxClientError, (req, res) -> {
                throw new ExternalApiException(
                    "Grade not found for " + rollNumber + ": " + res.getStatusCode());
            })
            .onStatus(HttpStatusCode::is5xxServerError, (req, res) -> {
                throw new ExternalApiException("External grade API unavailable");
            })
            .body(ExternalGradeDTO.class);  // Jackson deserialises automatically
    }

    public List<ExternalGradeDTO> importBulk(List<String> rollNumbers) {
        return restClient.post()
            .uri("/bulk-import")
            .contentType(MediaType.APPLICATION_JSON)
            .body(rollNumbers)  // Jackson serialises automatically
            .retrieve()
            .body(new ParameterizedTypeReference<List<ExternalGradeDTO>>() {});
    }
}
RestClient vs RestTemplate
RestTemplate still works but is in maintenance mode. New code in this project uses RestClient for all external HTTP calls.

Same GET call — RestTemplate vs RestClientMedium
// Old — RestTemplate
RestTemplate template = new RestTemplate();
ResponseEntity<ExternalGradeDTO> response = template.exchange(
    "https://api.example.com/students/{id}/grade",
    HttpMethod.GET,
    new HttpEntity<>(headers),
    ExternalGradeDTO.class,
    rollNumber);
ExternalGradeDTO grade = response.getBody();

// New — RestClient (Boot 3.2)
RestClient client = RestClient.create("https://api.example.com");
ExternalGradeDTO grade = client.get()
    .uri("/students/{id}/grade", rollNumber)
    .headers(h -> h.addAll(headers))
    .retrieve()
    .body(ExternalGradeDTO.class);
