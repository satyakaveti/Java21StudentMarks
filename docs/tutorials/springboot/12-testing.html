Spring Boot Testing

Three test types cover the whole stack: @SpringBootTest for full integration tests with a real PostgreSQL container, @WebMvcTest for controller slice tests (no DB), and @DataJpaTest for repository slice tests. Spring Boot 3.1's @ServiceConnection removes all boilerplate from Testcontainers setup.

Test Pyramid
This project has all three layers: unit tests (plain JUnit, no Spring), slice tests (@WebMvcTest, @DataJpaTest), and full integration tests (@SpringBootTest + Testcontainers).

@SpringBootTest
StudentResultsIntegrationTest starts the full app on a random port with a real PostgreSQL container — tests the complete HTTP→Service→DB→Response chain.
1 High Level Overview

@SpringBootTest(webEnvironment = RANDOM_PORT) starts the full Spring application context on a random free port. Use TestRestTemplate or WebTestClient to make real HTTP calls. Every layer — security, validation, cache, events, DB — is active. Expensive to start but tests real behaviour.

test/integration/StudentResultsIntegrationTest.java
@SpringBootTest(webEnvironment = SpringBootTest.WebEnvironment.RANDOM_PORT)
@Testcontainers
@ActiveProfiles("test")
class StudentResultsIntegrationTest {

    @Container
    @ServiceConnection  // Boot 3.1 — zero-config wiring, no @DynamicPropertySource needed
    static PostgreSQLContainer<?> postgres =
        new PostgreSQLContainer<>("postgres:16-alpine");

    @Container
    @ServiceConnection
    static GenericContainer<?> redis =
        new GenericContainer<>("redis:7-alpine").withExposedPorts(6379);

    @Autowired
    private TestRestTemplate restTemplate;

    @Autowired
    private StudentRepository studentRepository;

    @Test
    void fullFlowTest_adminCreatesStudent_studentViewsResults() {
        // 1. Login as admin
        var loginResp = restTemplate.postForEntity("/api/auth/login",
            new LoginRequest("admin", "password"), AuthResponse.class);
        assertThat(loginResp.getStatusCode()).isEqualTo(HttpStatus.OK);
        var token = loginResp.getBody().token();

        // 2. Admin creates student
        var headers = new HttpHeaders();
        headers.setBearerAuth(token);
        var createResp = restTemplate.exchange(
            "/api/admin/students",
            HttpMethod.POST,
            new HttpEntity<>(new CreateStudentRequest("S001","Arjun","a@s.com"), headers),
            StudentDTO.class);
        assertThat(createResp.getStatusCode()).isEqualTo(HttpStatus.CREATED);
        var studentId = createResp.getBody().id();

        // 3. Admin enters marks
        restTemplate.exchange(
            "/api/admin/students/" + studentId + "/marks",
            HttpMethod.POST,
            new HttpEntity<>(new CreateMarkRequest(1L, 87, LocalDate.now()), headers),
            MarkDTO.class);

        // 4. Student logs in and views results
        var studentLogin = restTemplate.postForEntity("/api/auth/login",
            new LoginRequest("S001", "password"), AuthResponse.class);
        var studentToken = studentLogin.getBody().token();

        var studentHeaders = new HttpHeaders();
        studentHeaders.setBearerAuth(studentToken);
        var resultsResp = restTemplate.exchange(
            "/api/results/me", HttpMethod.GET,
            new HttpEntity<>(studentHeaders),
            new ParameterizedTypeReference<List<MarkDTO>>() {});

        assertThat(resultsResp.getStatusCode()).isEqualTo(HttpStatus.OK);
        assertThat(resultsResp.getBody()).hasSize(1);
        assertThat(resultsResp.getBody().get(0).score()).isEqualTo(87);
    }
}
@WebMvcTest
StudentControllerTest and AdminControllerTest use @WebMvcTest — loads only the MVC layer, mocks the service with @MockBean, fast to run.
1 High Level Overview

@WebMvcTest(MyController.class) loads only the Spring MVC layer: controllers, filters, advice, converters. No service beans, no JPA, no Redis. Use @MockBean to stub service layer. Tests HTTP mappings, request validation, response codes, JSON serialisation, and security rules — without touching the DB.

@WebMvcTest(AdminController.class)
@ActiveProfiles("test")
class AdminControllerTest {

    @Autowired
    private MockMvc mockMvc;

    @Autowired
    private ObjectMapper objectMapper;

    @MockBean
    private StudentService studentService;   // mocked — no real DB

    @MockBean
    private ResultService resultService;

    @Test
    @WithMockUser(roles = "ADMIN")
    void createStudent_validRequest_returns201() throws Exception {
        var request = new CreateStudentRequest("S001", "Arjun Kumar", "arjun@school.com");
        var response = new StudentDTO(1L, "Arjun Kumar", "S001", "arjun@school.com");

        when(studentService.createStudent(request)).thenReturn(response);

        mockMvc.perform(post("/api/admin/students")
                .contentType(MediaType.APPLICATION_JSON)
                .content(objectMapper.writeValueAsString(request)))
            .andExpect(status().isCreated())
            .andExpect(jsonPath("$.id").value(1))
            .andExpect(jsonPath("$.name").value("Arjun Kumar"))
            .andExpect(jsonPath("$.rollNumber").value("S001"));
    }

    @Test
    @WithMockUser(roles = "STUDENT")   // wrong role
    void createStudent_asStudent_returns403() throws Exception {
        mockMvc.perform(post("/api/admin/students")
                .contentType(MediaType.APPLICATION_JSON)
                .content("{}"))
            .andExpect(status().isForbidden());
    }

    @Test
    @WithMockUser(roles = "ADMIN")
    void createStudent_blankName_returns400WithFieldError() throws Exception {
        var badRequest = new CreateStudentRequest("S001", "", "arjun@school.com");

        mockMvc.perform(post("/api/admin/students")
                .contentType(MediaType.APPLICATION_JSON)
                .content(objectMapper.writeValueAsString(badRequest)))
            .andExpect(status().isBadRequest())
            .andExpect(jsonPath("$.title").value("Validation Failed"))
            .andExpect(jsonPath("$.errors.name").exists());
    }
}
@DataJpaTest
MarkRepositoryTest uses @DataJpaTest — starts only JPA context with real SQL (via Testcontainers), tests custom @Query methods and derived queries against real PostgreSQL.
1 High Level Overview

@DataJpaTest loads only the JPA slice: entities, repositories, Flyway migrations. No web layer, no services. By default uses an in-memory H2 database. For PostgreSQL-specific queries (native SQL, ILIKE, JSONB), replace H2 with Testcontainers via @AutoConfigureTestDatabase(replace = NONE).

@Testcontainers
PostgreSQLContainer and Redis GenericContainer start real Docker containers for tests — no mocking, no H2 compatibility issues, real PostgreSQL 16 behaviour.
1 High Level Overview

Testcontainers starts real Docker containers in tests. @Testcontainers on the class activates lifecycle management. @Container on a field manages container start/stop. static containers are shared across all tests in the class (faster). Spring Boot 3.1's @ServiceConnection auto-wires the container's host/port into the datasource — no manual @DynamicPropertySource needed.

2 Examples
Before Boot 3.1 (DynamicPropertySource)Simple
// Old way — manual URL override
@Testcontainers
class OldStyleTest {
    @Container
    static PostgreSQLContainer<?> postgres =
        new PostgreSQLContainer<>("postgres:16-alpine");

    @DynamicPropertySource
    static void props(DynamicPropertyRegistry registry) {
        registry.add("spring.datasource.url",      postgres::getJdbcUrl);
        registry.add("spring.datasource.username", postgres::getUsername);
        registry.add("spring.datasource.password", postgres::getPassword);
    }
}
Boot 3.1+ — @ServiceConnection (zero config)Medium
// New way — @ServiceConnection handles everything
@Testcontainers
class NewStyleTest {
    @Container
    @ServiceConnection   // ← Boot 3.1 — auto-wires datasource URL/credentials
    static PostgreSQLContainer<?> postgres =
        new PostgreSQLContainer<>("postgres:16-alpine");

    // No @DynamicPropertySource needed!
    // Spring reads the container's actual port and sets spring.datasource.* automatically
}
@ServiceConnection (Spring Boot 3.1)
@ServiceConnection on PostgreSQLContainer and Redis GenericContainer auto-configures datasource and Redis connection — zero manual URL setup.
1 High Level Overview

Spring Boot 3.1 introduced @ServiceConnection — a declarative way to wire Testcontainers into Spring's auto-configuration. Works for PostgreSQL, MySQL, Redis, RabbitMQ, Kafka, MongoDB, and more. Spring detects the container type, reads its connection details after startup, and populates the appropriate spring.* properties. Completely eliminates boilerplate.

MockMvc
Used in @WebMvcTest — performs fake HTTP requests in-process, asserts status codes, response body JSON paths, and headers without starting a real server.
1 High Level Overview

MockMvc simulates HTTP calls through Spring's DispatcherServlet without starting a real server. The full MVC pipeline runs: filters, interceptors, controller, argument resolution, message conversion, exception handlers. Much faster than TestRestTemplate (no real TCP). Fluent API: perform() → andExpect() → andReturn().

@WithMockUser
Sets up a fake authenticated user in the SecurityContext for the test — no real JWT needed. Test STUDENT access, ADMIN access, and unauthenticated access in the same test class.
1 High Level Overview

@WithMockUser injects a fake Authentication into the SecurityContextHolder for the duration of the test. Specify username, roles, or authorities. For testing @PreAuthorize expressions that reference authentication.principal.id, create a custom @WithMockUser using @WithSecurityContext.

@MockBean
@MockBean replaces the real StudentService and ResultService with Mockito mocks in controller tests — tests the controller in isolation from business logic.
1 High Level Overview

@MockBean creates a Mockito mock and registers it in the Spring context, replacing any existing bean of that type. When you when(mock.method()).thenReturn(value), the controller gets the stub. After each test, the mock is reset. Use @SpyBean to wrap a real bean and only stub specific methods.

@ParameterizedTest
Grade boundary tests use @ParameterizedTest + @CsvSource — tests all 8 grade thresholds (0, 34, 35, 49, 50, 74, 75, 100) in one compact test method.
1 High Level Overview

@ParameterizedTest runs the test multiple times with different inputs. @CsvSource is the most readable source for simple value + expected pairs. Also available: @ValueSource, @MethodSource, @EnumSource, @CsvFileSource. Each invocation is reported separately in test results.

test/service/GradeCalculatorTest.java
class GradeCalculatorTest {

    private final GradeCalculator calculator = new GradeCalculator();

    @ParameterizedTest(name = "score={0} → grade={1}, passed={2}")
    @CsvSource({
        //  score, grade, passed
        "  0,       F,    false",
        " 34,       F,    false",
        " 35,       C,    true",
        " 49,       C,    true",
        " 50,       B,    true",
        " 74,       B,    true",
        " 75,       A,    true",
        "100,       A,    true"
    })
    void gradeCalculation(int score, String expectedGrade, boolean expectedPassed) {
        var result = calculator.calculate(score);
        assertThat(result.grade()).isEqualTo(expectedGrade);
        assertThat(result.passed()).isEqualTo(expectedPassed);
    }
}
