Spring Security 6

Stateless JWT authentication with two roles — STUDENT and ADMIN. Every request carries a Bearer token; the JwtAuthFilter validates it and populates the SecurityContext. Method-level security with @PreAuthorize ensures students can only see their own data.

SecurityFilterChain
The entire security configuration lives in SecurityConfig.filterChain() — no more extending WebSecurityConfigurerAdapter (removed in Spring Security 6).
1 High Level Overview

Spring Security 6 replaced the old WebSecurityConfigurerAdapter with a SecurityFilterChain bean. You declare a chain of filters, endpoint access rules, session policy, and pluggable components (JWT filter, OAuth2, etc.) all in one place using a fluent DSL. Multiple chains can exist with different securityMatcher paths.

2 Examples
Minimal JWT filter chainSimple
@Configuration
@EnableWebSecurity
public class SecurityConfig {

    @Bean
    public SecurityFilterChain filterChain(HttpSecurity http) throws Exception {
        return http
            .csrf(AbstractHttpConfigurer::disable)          // stateless API — no CSRF needed
            .sessionManagement(s -> s
                .sessionCreationPolicy(SessionCreationPolicy.STATELESS))
            .authorizeHttpRequests(auth -> auth
                .requestMatchers("/api/auth/**").permitAll() // login + register = public
                .anyRequest().authenticated())               // everything else needs a token
            .addFilterBefore(jwtAuthFilter, UsernamePasswordAuthenticationFilter.class)
            .build();
    }
}
Full production filter chainReal-time
@Configuration
@EnableWebSecurity
@EnableMethodSecurity   // activates @PreAuthorize, @PostAuthorize
public class SecurityConfig {

    private final JwtAuthFilter jwtAuthFilter;
    private final OAuth2AuthenticationSuccessHandler oAuth2SuccessHandler;

    public SecurityConfig(JwtAuthFilter jwtAuthFilter,
                          OAuth2AuthenticationSuccessHandler oAuth2SuccessHandler) {
        this.jwtAuthFilter = jwtAuthFilter;
        this.oAuth2SuccessHandler = oAuth2SuccessHandler;
    }

    @Bean
    public SecurityFilterChain filterChain(HttpSecurity http) throws Exception {
        return http
            .csrf(AbstractHttpConfigurer::disable)
            .cors(cors -> cors.configurationSource(corsConfigurationSource()))
            .sessionManagement(s -> s
                .sessionCreationPolicy(SessionCreationPolicy.STATELESS))
            .authorizeHttpRequests(auth -> auth
                .requestMatchers("/api/auth/**").permitAll()
                .requestMatchers("/actuator/health").permitAll()
                .requestMatchers("/api/admin/**").hasRole("ADMIN")
                .requestMatchers("/api/results/**").hasAnyRole("STUDENT", "ADMIN")
                .anyRequest().authenticated())
            .addFilterBefore(jwtAuthFilter, UsernamePasswordAuthenticationFilter.class)
            .oauth2Login(oauth2 -> oauth2
                .successHandler(oAuth2SuccessHandler))
            .exceptionHandling(ex -> ex
                .authenticationEntryPoint(new HttpStatusEntryPoint(HttpStatus.UNAUTHORIZED))
                .accessDeniedHandler(customAccessDeniedHandler()))
            .build();
    }
}
Stateless JWT Session
SessionCreationPolicy.STATELESS — no HttpSession, no cookies for auth. Every request must carry a Bearer token in the Authorization header.
1 High Level Overview

Traditional web apps store authentication in the server-side HTTP session. REST APIs are stateless — no session. Instead, the client includes a JWT (JSON Web Token) in every request header: Authorization: Bearer <token>. The server validates the token cryptographically, extracts the user, and authorises the request — no DB lookup needed for every request.

2 Examples
Login flow — returns JWTMedium
// POST /api/auth/login  { "username": "arjun", "password": "secret" }
// Response: { "token": "eyJhbGci...", "expiresIn": 3600 }

@PostMapping("/login")
public ResponseEntity<AuthResponse> login(
        @Valid @RequestBody LoginRequest request) {

    // Throws BadCredentialsException if wrong password
    var auth = authenticationManager.authenticate(
        new UsernamePasswordAuthenticationToken(
            request.username(), request.password()));

    var user = (UserDetails) auth.getPrincipal();
    var token = jwtService.generateToken(user);
    return ResponseEntity.ok(new AuthResponse(token, 3600));
}
JwtAuthFilter
Intercepts every request, extracts the Bearer token, validates it with JwtService, and populates SecurityContextHolder so @PreAuthorize and @AuthenticationPrincipal work.
1 High Level Overview

OncePerRequestFilter guarantees exactly one execution per request (vs once per dispatch). The JWT filter: reads the Authorization header → extracts the token → validates with JwtService → loads the user → sets SecurityContextHolder. If validation fails, it does nothing — the request proceeds unauthenticated and Spring Security's entry point returns 401.

3 In This Project
security/JwtAuthFilter.java
@Component
public class JwtAuthFilter extends OncePerRequestFilter {

    private final JwtService jwtService;
    private final UserDetailsService userDetailsService;

    public JwtAuthFilter(JwtService jwtService,
                         UserDetailsService userDetailsService) {
        this.jwtService = jwtService;
        this.userDetailsService = userDetailsService;
    }

    @Override
    protected void doFilterInternal(HttpServletRequest request,
                                     HttpServletResponse response,
                                     FilterChain filterChain)
            throws ServletException, IOException {

        final String authHeader = request.getHeader("Authorization");

        // No token? Skip — let Spring Security handle as unauthenticated
        if (authHeader == null || !authHeader.startsWith("Bearer ")) {
            filterChain.doFilter(request, response);
            return;
        }

        final String jwt = authHeader.substring(7);
        final String username = jwtService.extractUsername(jwt);

        // Only set authentication if not already set and token is valid
        if (username != null
                && SecurityContextHolder.getContext().getAuthentication() == null) {
            var userDetails = userDetailsService.loadUserByUsername(username);
            if (jwtService.isTokenValid(jwt, userDetails)) {
                var authToken = new UsernamePasswordAuthenticationToken(
                    userDetails, null, userDetails.getAuthorities());
                authToken.setDetails(
                    new WebAuthenticationDetailsSource().buildDetails(request));
                SecurityContextHolder.getContext().setAuthentication(authToken);
            }
        }
        filterChain.doFilter(request, response);
    }
}
JwtService
Generates signed JWTs on login, validates them on every request, and extracts claims (username, roles, expiry).
1 High Level Overview

A JWT has three base64-encoded parts: Header (algorithm), Payload (claims: sub, roles, exp, iat), and Signature (HMAC-SHA256 of header+payload using a secret key). JwtService uses the io.jsonwebtoken (jjwt) library to build, sign, parse, and validate tokens. The secret key comes from AppProperties (environment variable).

3 In This Project
security/JwtService.java
@Service
public class JwtService {

    private final AppProperties appProperties;

    public JwtService(AppProperties appProperties) {
        this.appProperties = appProperties;
    }

    public String generateToken(UserDetails userDetails) {
        var roles = userDetails.getAuthorities().stream()
            .map(GrantedAuthority::getAuthority)
            .toList();

        return Jwts.builder()
            .subject(userDetails.getUsername())
            .claim("roles", roles)
            .issuedAt(new Date())
            .expiration(new Date(System.currentTimeMillis()
                + appProperties.jwtExpirationMinutes() * 60_000L))
            .signWith(getSigningKey())
            .compact();
    }

    public String extractUsername(String token) {
        return extractClaim(token, Claims::getSubject);
    }

    public boolean isTokenValid(String token, UserDetails userDetails) {
        var username = extractUsername(token);
        return username.equals(userDetails.getUsername()) && !isTokenExpired(token);
    }

    private boolean isTokenExpired(String token) {
        return extractClaim(token, Claims::getExpiration).before(new Date());
    }

    private <T> T extractClaim(String token, Function<Claims, T> resolver) {
        var claims = Jwts.parser()
            .verifyWith(getSigningKey()).build()
            .parseSignedClaims(token).getPayload();
        return resolver.apply(claims);
    }

    private SecretKey getSigningKey() {
        byte[] keyBytes = Decoders.BASE64.decode(appProperties.jwtSecret());
        return Keys.hmacShaKeyFor(keyBytes);
    }
}
BCryptPasswordEncoder
Passwords are hashed with BCrypt strength 12 before saving. Never stored in plain text. Compared using encoder.matches() — never by string equality.
1 High Level Overview

BCrypt is a one-way adaptive hashing function. Each hash includes a random salt, making rainbow table attacks infeasible. Strength 12 means 2^12 = 4096 hashing rounds — slow enough to resist brute force, fast enough for login. Spring Security uses DelegatingPasswordEncoder by default which supports multiple encoders, but for new projects BCrypt is the standard choice.

@PreAuthorize
Admin-only endpoints use hasRole('ADMIN'). Student endpoints use SpEL to verify the studentId in the path matches the logged-in student's own ID.
1 High Level Overview

@PreAuthorize runs a Spring Expression Language (SpEL) expression before the method executes. If the expression returns false, Spring throws AccessDeniedException (→ 403). You can check roles, permissions, and even method parameters — allowing resource-owner checks like "only the student whose ID matches can see this".

2 Examples
Role checkSimple
@DeleteMapping("/students/{id}")
@PreAuthorize("hasRole('ADMIN')")   // 403 if not ADMIN
public void deleteStudent(@PathVariable Long id) {
    studentService.softDeleteStudent(id);
}

@GetMapping("/students")
@PreAuthorize("hasAnyRole('ADMIN', 'STUDENT')")
public List<StudentDTO> list() { ... }
Owner check — student sees only their own dataMedium
// #studentId refers to the method parameter
// authentication.principal.id is the logged-in user's ID from the JWT
@GetMapping("/students/{studentId}/results")
@PreAuthorize("hasRole('ADMIN') or #studentId == authentication.principal.id")
public List<MarkDTO> getResults(@PathVariable Long studentId) {
    return resultService.getResults(studentId);
}
// ADMIN → always allowed
// STUDENT → only allowed if their own ID matches the path variable

@PostAuthorize
Used to filter response fields after the method returns — e.g. hiding the student's email from the response if the caller is not an ADMIN.
1 High Level Overview

@PostAuthorize runs after the method executes, with the return value available as returnObject. Use it when you need to check something on the result — like ensuring a returned student record belongs to the caller. Less common than @PreAuthorize but powerful for fine-grained field-level security.

2 Examples
Verify returned object belongs to callerMedium
@GetMapping("/students/{id}")
@PostAuthorize("hasRole('ADMIN') or returnObject.username == authentication.name")
public StudentDTO getStudent(@PathVariable Long id) {
    return studentService.getStudentById(id);
    // After method runs: if caller is STUDENT and returnObject.username != their name → 403
}
@EnableMethodSecurity
Placed on SecurityConfig — activates @PreAuthorize and @PostAuthorize processing across all beans.
1 High Level Overview

@EnableMethodSecurity replaces the older @EnableGlobalMethodSecurity. It activates AOP-based interception for @PreAuthorize, @PostAuthorize, @PreFilter, @PostFilter, and JSR-250 annotations (@RolesAllowed). Without this annotation, all method-level security annotations are silently ignored.

OAuth2 Google Login
Students can log in with Google as an alternative to username/password. On first Google login, a student account is auto-created and linked.
1 High Level Overview

Spring Security's OAuth2 client handles the entire Google login redirect flow. You configure client credentials in application.yml; Spring does the rest. A custom OAuth2AuthenticationSuccessHandler fires after successful Google auth to create or link a local student account and issue a JWT — so the frontend still gets a Bearer token regardless of login method.

3 In This Project
security/OAuth2AuthenticationSuccessHandler.java
@Component
public class OAuth2AuthenticationSuccessHandler
        extends SimpleUrlAuthenticationSuccessHandler {

    private final UserRepository userRepository;
    private final JwtService jwtService;

    public OAuth2AuthenticationSuccessHandler(UserRepository userRepository,
                                               JwtService jwtService) {
        this.userRepository = userRepository;
        this.jwtService = jwtService;
    }

    @Override
    public void onAuthenticationSuccess(HttpServletRequest request,
                                         HttpServletResponse response,
                                         Authentication authentication)
            throws IOException {
        var oauth2User = (OAuth2User) authentication.getPrincipal();
        var email = oauth2User.getAttribute("email").toString();
        var name  = oauth2User.getAttribute("name").toString();

        // Create account on first login
        var user = userRepository.findByEmail(email)
            .orElseGet(() -> userRepository.save(
                User.builder().email(email).name(name)
                    .role(Role.STUDENT).build()));

        // Issue JWT — same as username/password login
        var token = jwtService.generateToken(user);

        // Redirect to frontend with token
        getRedirectStrategy().sendRedirect(request, response,
            "http://localhost:3000/auth/callback?token=" + token);
    }
}
401 & 403 Handlers
Returns clean JSON 401/403 ProblemDetail responses instead of Spring Security's default HTML error pages — essential for a REST API consumed by a JS frontend.
1 High Level Overview

AuthenticationEntryPoint fires when an unauthenticated request reaches a protected endpoint (missing or invalid token → 401). AccessDeniedHandler fires when an authenticated user lacks permission (wrong role → 403). By default, Spring Security returns HTML — for REST APIs, override both to return ProblemDetail JSON.

3 In This Project
config/SecurityConfig.java — exception handling
@Bean
public SecurityFilterChain filterChain(HttpSecurity http) throws Exception {
    return http
        // ... other config ...
        .exceptionHandling(ex -> ex
            // 401 — no token or invalid token
            .authenticationEntryPoint(new HttpStatusEntryPoint(HttpStatus.UNAUTHORIZED))
            // 403 — authenticated but wrong role
            .accessDeniedHandler(customAccessDeniedHandler()))
        .build();
}

@Bean
public AccessDeniedHandler customAccessDeniedHandler() {
    return (request, response, ex) -> {
        response.setStatus(HttpStatus.FORBIDDEN.value());
        response.setContentType(MediaType.APPLICATION_JSON_VALUE);
        var problem = ProblemDetail.forStatusAndDetail(
            HttpStatus.FORBIDDEN, "You do not have permission to access this resource");
        problem.setTitle("Forbidden");
        new ObjectMapper().writeValue(response.getWriter(), problem);
    };
}
