The last stop before Java 21 LTS. Scoped values enter incubation. Record patterns and virtual threads continue maturing toward their Java 21 graduation.

Scoped Values JEP 429 — Incubator → Preview in Java 21
Used in this project — pass UserPrincipal through the request call chain without ThreadLocal.
1 High Level Overview

Scoped values are an alternative to ThreadLocal — they pass immutable contextual data through a call chain without threading it through method parameters. Unlike ThreadLocal: scoped values are immutable (no set()), automatically cleaned up when the scope ends, and work correctly with virtual threads (where ThreadLocal inheritance is problematic). Bound with ScopedValue.where(...).run(...).

2 Examples
ThreadLocal vs ScopedValueSimple
// ThreadLocal — mutable, inherited by child threads, leaks if not removed
static ThreadLocal<User> CURRENT_USER = new ThreadLocal<>();
CURRENT_USER.set(user);
doWork();  // CURRENT_USER.get() works inside
CURRENT_USER.remove();  // must manually clean up!

// ScopedValue — immutable, scoped, works with virtual threads
static ScopedValue<User> CURRENT_USER = ScopedValue.newInstance();

ScopedValue.where(CURRENT_USER, user).run(() -> {
    doWork();  // CURRENT_USER.get() works inside
});
// Automatically cleaned up after run() completes
Request-scoped user contextMedium
public class RequestContext {
    public static final ScopedValue<UserPrincipal> USER =
        ScopedValue.newInstance();
    public static final ScopedValue<String> REQUEST_ID =
        ScopedValue.newInstance();
}

// In filter/interceptor — bind for duration of request
ScopedValue.where(RequestContext.USER, principal)
    .where(RequestContext.REQUEST_ID, UUID.randomUUID().toString())
    .run(() -> filterChain.doFilter(request, response));

// In any service — no parameter needed, no SecurityContext
void recordAudit(String action) {
    var user = RequestContext.USER.get();
    auditRepo.save(new AuditLog(action, user.getUsername(), LocalDateTime.now()));
}
3 In This Project
security/JwtAuthFilter.java · aspect/AuditAspect.java
// UserContext.java
public class UserContext {
    public static final ScopedValue<UserPrincipal> CURRENT_USER =
        ScopedValue.newInstance();

    public static UserPrincipal currentUser() {
        return CURRENT_USER.get();
    }
    public static boolean isAdmin() {
        return CURRENT_USER.isBound() && CURRENT_USER.get().isAdmin();
    }
}

// JwtAuthFilter — bind after JWT validation
ScopedValue.where(UserContext.CURRENT_USER, principal)
    .run(() -> filterChain.doFilter(request, response));

// AuditAspect — no @AuthenticationPrincipal injection needed
@Around("@annotation(Auditable)")
public Object audit(ProceedingJoinPoint pjp) throws Throwable {
    var user = UserContext.currentUser();
    var result = pjp.proceed();
    auditRepo.save(new AuditLog(
        pjp.getSignature().getName(),
        user.getUsername(),
        LocalDateTime.now()
    ));
    return result;
}
Record Pattern Enhancements JEP 432 — 2nd Preview
Further matured in Java 20 — standard in Java 21. Same syntax used in this project's controller dispatch.
1 High Level Overview

Java 20 refined record patterns with improvements to generic type inference in patterns, exhaustiveness analysis for sealed hierarchies in switch, and alignment with unnamed pattern variables. These refinements addressed edge cases found during Java 19 preview feedback and paved the way for the final Java 21 standard form.

2 Examples
Generic record patternsSimple
// Java 20 improved generic type inference in record patterns
sealed interface Box<T> permits Box.Full, Box.Empty {}
record Full<T>(T value) implements Box<T> {}
record Empty<T>()       implements Box<T> {}

// Java 19 — needed explicit type
case Box.Full<String>(var s) -> ...

// Java 20 — inferred
case Box.Full(var s) -> ...  // s inferred as String when Box<String>
Virtual Thread Updates JEP 436 — 2nd Preview
Used in this project — virtual threads became standard in Java 21, these updates built toward that.
1 High Level Overview

Java 20 continued refining virtual threads based on Java 19 preview feedback. Key improvements: Thread.sleep() on virtual threads now correctly parks (doesn't pin the carrier), improvements to synchronized block handling, and better JDK tooling support (JFR, JConsole, debuggers) for virtual thread visibility. Also: ThreadLocal in virtual threads: inheritable ThreadLocal values are no longer inherited by default in virtual threads for scalability.

2 Examples
Virtual thread pinning awarenessMedium
// Virtual thread pinning — avoid synchronized blocks with blocking I/O
// This PINS the carrier thread (bad)
synchronized (lock) {
    String data = Files.readString(path);  // blocks, pins carrier!
}

// Use ReentrantLock instead (doesn't pin)
ReentrantLock lock = new ReentrantLock();
lock.lock();
try {
    String data = Files.readString(path);  // blocks, parks virtual thread safely
} finally {
    lock.unlock();
}
