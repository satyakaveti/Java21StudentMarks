Java 8 — The Functional Revolution

The most impactful Java release before 21. Introduced functional programming, the Stream API, Optional, and a modern Date/Time API. Most production Java code today still relies heavily on Java 8 features.

Lambda Expressions
Used in this project — filter/sort student lists, compose validators, event handlers.
1 High Level Overview

Lambdas are anonymous functions passed as values. They implement functional interfaces — interfaces with exactly one abstract method. Syntax: (params) -> expression or (params) -> { body }. They replaced verbose anonymous inner classes and enabled functional-style programming in Java.

2 Examples
Sort a listSimple
List<String> names = Arrays.asList("Charlie", "Alice", "Bob");

// Before Java 8 — anonymous class
Collections.sort(names, new Comparator<String>() {
    public int compare(String a, String b) { return a.compareTo(b); }
});

// Lambda
Collections.sort(names, (a, b) -> a.compareTo(b));

// Method reference (even shorter)
names.sort(String::compareTo);
Filter + transform a listMedium
List<Student> students = getStudents();

// Lambda in stream pipeline
List<String> passingNames = students.stream()
    .filter(s -> s.getTotalMarks() >= 35)
    .sorted((a, b) -> b.getTotalMarks() - a.getTotalMarks())
    .map(Student::getName)
    .collect(Collectors.toList());

// Compose predicates using and() / or()
Predicate<Student> isPassing = s -> s.getTotalMarks() >= 35;
Predicate<Student> isActive  = s -> !s.isDeleted();
students.stream()
    .filter(isPassing.and(isActive))
    .forEach(s -> System.out.println(s.getName()));
Event-driven handler registrationReal-time
// Register multiple handlers for the same event using lambdas
bus.register("MARKS_UPDATED", event -> emailService.notify(event));
bus.register("MARKS_UPDATED", event -> auditLog.record(event));
bus.register("MARKS_UPDATED", event -> cache.evict(event.getStudentId()));

// All three fire when marks are updated
bus.publish(new MarksUpdatedEvent(studentId, marks));

Stream API
Used in this project — calculate averages, total marks, pass/fail counts, group by subject.
1 High Level Overview

Streams provide a declarative, pipeline-based approach to processing collections. A stream has a source, zero or more intermediate operations (lazy — filter, map, sorted), and one terminal operation (eager — collect, count, reduce). Streams don't modify the source and can be parallelised with parallelStream().

2 Examples
Count and average marksSimple
List<Integer> marks = List.of(78, 45, 92, 34, 67, 55);

long passing = marks.stream().filter(m -> m >= 35).count(); // 5

OptionalDouble avg = marks.stream()
    .mapToInt(Integer::intValue).average(); // 61.8
Group marks by subjectMedium
Map<String, Double> avgBySubject = allMarks.stream()
    .collect(Collectors.groupingBy(
        m -> m.getSubject().getName(),
        Collectors.averagingInt(Mark::getScore)
    ));
// {MATHS=72.5, SCIENCE=68.0, ENGLISH=75.3}

// Top 3 students by total
List<Student> top3 = allMarks.stream()
    .collect(Collectors.groupingBy(Mark::getStudent,
                Collectors.summingInt(Mark::getScore)))
    .entrySet().stream()
    .sorted(Map.Entry.<Student,Integer>comparingByValue().reversed())
    .limit(3).map(Map.Entry::getKey).collect(Collectors.toList());

public ResultSummaryDTO getSummary(Long studentId) {
    var marks = markRepository.findByStudentId(studentId);
    int total      = marks.stream().mapToInt(Mark::getScore).sum();
    double average = marks.stream().mapToInt(Mark::getScore).average().orElse(0.0);
    long passCount = marks.stream().filter(m -> m.getScore() >= 35).count();
    Map<String, Integer> bySubject = marks.stream()
        .collect(Collectors.toMap(m -> m.getSubject().getName(), Mark::getScore));
    return new ResultSummaryDTO(studentId, total, average, passCount, bySubject);
}
Functional Interfaces
Used in this project — custom mark validators composed with and().
1 High Level Overview

A functional interface has exactly one abstract method and is annotated with @FunctionalInterface. Java 8 ships built-in ones in java.util.function: Predicate<T> (test), Function<T,R> (apply), Consumer<T> (accept), Supplier<T> (get), BiFunction<T,U,R>. You can also define your own.

2 Examples
Built-in functional interfacesSimple
Predicate<Integer> isAdult = age -> age >= 18;
Function<String, Integer> strLen = String::length;
Consumer<String> printer = System.out::println;
Supplier<List<String>> listFactory = ArrayList::new;

isAdult.test(20);        // true
strLen.apply("hello");   // 5
printer.accept("hi");    // prints hi
listFactory.get();       // new ArrayList
Custom functional interfaceMedium
@FunctionalInterface
interface MarkValidator {
    boolean validate(int score);

    default MarkValidator and(MarkValidator other) {
        return score -> this.validate(score) && other.validate(score);
    }
}

MarkValidator notNegative = score -> score >= 0;
MarkValidator notOver100  = score -> score <= 100;
MarkValidator valid = notNegative.and(notOver100);
valid.validate(85);  // true
valid.validate(110); // false

Default Methods
Used in this project — Auditable interface provides isRecentlyModified() default.
1 High Level Overview

Default methods allow interfaces to have implementations, enabling you to add new methods to existing interfaces without breaking all implementors. They enable mixin-style composition and are how Java added methods like List.sort(), Map.computeIfAbsent(), and Iterable.forEach() without breaking backwards compatibility.

2 Examples
Interface with default methodSimple
interface Greeter {
    String name();  // abstract

    default String greet() {            // default — free implementation
        return "Hello, " + name() + "!";
    }
    default String greetFormal() {
        return "Good day, " + name() + ".";
    }
}

class Student implements Greeter {
    public String name() { return "Alice"; }
    // gets greet() and greetFormal() for free
}

domain/Student.java (Auditable interface concept)
public interface Auditable {
    LocalDateTime getLastModifiedAt();
    String getLastModifiedBy();

    // Default — all entities implementing Auditable get this free
    default boolean isRecentlyModified() {
        return Duration.between(getLastModifiedAt(), LocalDateTime.now())
                       .toHours() < 24;
    }
    default String auditSummary() {
        return "Modified by %s at %s".formatted(
            getLastModifiedBy(),
            getLastModifiedAt().format(DateTimeFormatter.ISO_LOCAL_DATE_TIME));
    }
}
Optional<T>
Used in this project — findById, findByStudentCode, fallback lookups.
1 High Level Overview

Optional<T> is a container that may or may not hold a value. It makes nullability explicit in the API, forcing callers to handle the empty case. Key methods: isPresent(), get(), orElse(), orElseThrow(), map(), filter(), ifPresent(). Java 9 added or() and ifPresentOrElse().

2 Examples
orElseThrowSimple
// Without Optional — NPE risk
Student s = repo.findById(id);       // could return null
System.out.println(s.getName());     // NPE if null!

// With Optional
Student s = repo.findById(id)
    .orElseThrow(() -> new StudentNotFoundException(id));
System.out.println(s.getName());     // safe
Chain map and filterMedium
// Get email of student's linked user, only if active
Optional<String> email = studentRepository.findById(studentId)
    .map(Student::getUser)
    .filter(User::isActive)
    .map(User::getEmail);

email.ifPresent(e -> emailService.send(e, "Welcome back!"));

Date & Time API (java.time)
Used in this project — exam dates, result timestamps, Duration for audit age.
1 High Level Overview

Java 8 replaced the broken java.util.Date and Calendar with the immutable, thread-safe java.time API (JSR-310). Key classes: LocalDate, LocalDateTime, ZonedDateTime, Instant, Duration, Period, DateTimeFormatter. All immutable — operations return new instances.

2 Examples
Date arithmeticSimple
LocalDate examDate = LocalDate.of(2024, 3, 15);
LocalDate today    = LocalDate.now();
long daysUntil = ChronoUnit.DAYS.between(today, examDate);

LocalDateTime resultAt = LocalDateTime.now();
Duration age = Duration.between(resultAt, LocalDateTime.now());
boolean isRecent = age.toMinutes() < 30;
Timezone-aware schedulingMedium
ZonedDateTime examIST = ZonedDateTime.of(
    LocalDateTime.of(2024, 6, 15, 10, 0),
    ZoneId.of("Asia/Kolkata"));

ZonedDateTime examUTC = examIST.withZoneSameInstant(ZoneOffset.UTC);
Instant examInstant   = examIST.toInstant();

// Format for display
String display = examIST.format(
    DateTimeFormatter.ofPattern("dd MMM yyyy, hh:mm a z"));

// AuditAspect — measure execution duration
@Around("@annotation(Auditable)")
public Object audit(ProceedingJoinPoint pjp) throws Throwable {
    Instant start = Instant.now();
    Object result = pjp.proceed();
    Duration elapsed = Duration.between(start, Instant.now());
    if (elapsed.toMillis() > 500)
        log.warn("Slow: {} took {}ms", pjp.getSignature().getName(), elapsed.toMillis());
    return result;
}
CompletableFuture
Used in this project — async report generation, async email dispatch.
1 High Level Overview

CompletableFuture enables non-blocking async programming. Unlike Future, it can be chained (thenApply, thenCompose), combined (allOf, anyOf), and has exception handling (exceptionally, handle). In Java 21 with virtual threads, many async use cases simplify to blocking code — but CompletableFuture remains useful for fire-and-forget and parallel fan-out.

2 Examples
Run async, chain resultsSimple
CompletableFuture<String> future = CompletableFuture
    .supplyAsync(() -> fetchStudentName(id))       // runs on ForkJoinPool
    .thenApply(name -> "Hello, " + name)           // transform result
    .thenApply(String::toUpperCase);               // chain

String result = future.get();  // block until done
Parallel fan-out with allOfMedium
CompletableFuture<Void> email = CompletableFuture
    .runAsync(() -> emailService.sendAlert(studentId));
CompletableFuture<Void> audit = CompletableFuture
    .runAsync(() -> auditLog.record("MARKS_PUBLISHED", studentId));

CompletableFuture.allOf(email, audit)
    .exceptionally(ex -> { log.error("Async failed", ex); return null; })
    .join();

Nashorn JavaScript Engine
Not used in this project. Nashorn was deprecated in Java 11 and removed in Java 15. GraalVM's polyglot API is the modern replacement.
1 High Level Overview

Nashorn was a JavaScript engine bundled with the JDK, allowing Java programs to execute JavaScript code and vice versa. It replaced the older Rhino engine and offered better performance via invokedynamic. Deprecated in Java 11 (too costly to maintain ES spec compliance) and removed in Java 15.

2 Examples
Execute JS from Java (historical)Simple
// Java 8–10 only — Nashorn was removed in Java 15
ScriptEngine engine = new ScriptEngineManager().getEngineByName("nashorn");
engine.eval("print('Hello from JavaScript')");

// Call Java from JS
engine.eval("var list = java.util.Arrays.asList(1, 2, 3); print(list.size())");

// Modern alternative: GraalVM polyglot
// Context ctx = Context.create(); ctx.eval("js", "print('hello')");
