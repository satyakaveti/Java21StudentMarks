Java 12 — Switch Expressions & Shenandoah GC

Introduced switch expressions as a preview feature and the Shenandoah GC. Switch expressions would graduate to standard in Java 14.

Switch Expressions JEP 325 — Preview
Used in this project — grade letter mapping: marks range → A/B/C/F. Standard in Java 14.
1 High Level Overview

Switch expressions extend the switch statement so it can return a value. The new arrow syntax (case X -> value) eliminates fall-through bugs and the need for break. Multiple labels per arm: case A, B -> .... The yield keyword (added in Java 13) returns a value from a block arm. Exhaustiveness checked at compile time.

2 Examples
Arrow syntax — no fall-throughSimple
// Old switch statement — fall-through risk, verbose
String grade;
switch (score / 25) {
    case 4:  grade = "A"; break;
    case 3:  grade = "B"; break;
    case 2:  grade = "C"; break;
    default: grade = "F";
}

// Switch expression — concise, no fall-through
String grade = switch (score / 25) {
    case 4    -> "A";
    case 3    -> "B";
    case 2    -> "C";
    default   -> "F";
};
Multiple labels + yieldMedium
String status = switch (grade) {
    case "A", "B", "C" -> "PASS";    // multiple labels in one arm
    case "F"           -> "FAIL";
    default            -> {
        log.warn("Unknown grade: {}", grade);
        yield "UNKNOWN";              // yield from block arm
    }
};

// Switch expression used as method return
public String passOrFail(String grade) {
    return switch (grade) {
        case "A", "B", "C" -> "PASS";
        case "F"           -> "FAIL";
        default -> throw new IllegalArgumentException("Invalid grade: " + grade);
    };
}
Grade calculation in serviceReal-time
// Java 21 guarded patterns in switch (evolved from this)
private String calculateGrade(int score) {
    return switch (score) {
        case int s when s >= 75 -> "A";
        case int s when s >= 50 -> "B";
        case int s when s >= 35 -> "C";
        default                 -> "F";
    };
}

Shenandoah GC JEP 189
Not used in this project. This project uses Generational ZGC (Java 21). Shenandoah is an alternative low-pause GC option.
1 High Level Overview

Shenandoah is a low-pause-time GC that performs concurrent compaction — it moves live objects while the application is running, not during stop-the-world pauses. Unlike G1, pause times are independent of heap size. It targets applications that need consistent low latency. Originally a Red Hat contribution.

2 Examples
Enable ShenandoahSimple
// JVM flag
java -XX:+UseShenandoahGC -Xms512m -Xmx2g -jar student.jar

// Shenandoah vs ZGC:
// Both: sub-ms pauses, concurrent compaction
// Shenandoah: better for constrained heaps (<4GB)
// ZGC (Java 21): better scalability, Generational support added
JVM Constants API JEP 334
Not used in this project. This is a JVM/framework-level API used by bytecode manipulation libraries and compilers, not typical application code.
1 High Level Overview

The JVM Constants API (java.lang.constant) provides a standard model for describing loadable constants — values that appear in the constant pool of a class file (CONSTANT_Class, CONSTANT_MethodHandle, etc.). Used by tools like ASM, byte-buddy, and the compiler itself. Key types: ClassDesc, MethodTypeDesc, MethodHandleDesc, DynamicConstantDesc.

2 Examples
ClassDesc and MethodTypeDescSimple
// Describe a class symbolically (used by compilers/tools)
ClassDesc studentDesc = ClassDesc.of("com.studentresults.domain.Student");
ClassDesc listDesc    = ClassDesc.of("java.util.List");

// Describe a method type
MethodTypeDesc mtd = MethodTypeDesc.of(
    ClassDesc.of("java.lang.String"),  // return type
    ClassDesc.ofDescriptor("I")        // int parameter
);
// Most application code never uses this directly
