Java 9 — Modules, JShell & Stream Polish

Introduced the Java Platform Module System (JPMS) — the biggest structural change since Java 1.0. Also added JShell, immutable collection factories, and useful Stream/Optional enhancements.

Module System (JPMS) JEP 261
Not directly used in this project. Spring Boot's auto-configuration and classpath scanning work on the unnamed module. JPMS is most relevant for SDK/library authors.
1 High Level Overview

The Java Platform Module System (Project Jigsaw) allows you to declare a module with explicit dependencies and exports. A module-info.java file at the root declares the module name, what it requires, what it exports, and what services it provides/uses. This enables strong encapsulation at the package level and reliable configuration.

2 Examples
Declare a moduleSimple
// module-info.java
module com.studentresults.api {
    requires java.base;           // implicit, shown for clarity
    requires spring.web;
    requires spring.data.jpa;
    exports com.studentresults.dto;     // only dto package visible to others
    exports com.studentresults.api;
    // com.studentresults.service is NOT exported — internal only
}
Multi-module projectMedium
// module: com.studentresults.domain
module com.studentresults.domain {
    exports com.studentresults.domain;
}

// module: com.studentresults.service
module com.studentresults.service {
    requires com.studentresults.domain;  // can use domain classes
    exports com.studentresults.service;
}

// module: com.studentresults.web
module com.studentresults.web {
    requires com.studentresults.service;  // can use service, transitively domain
    requires java.net.http;
}
JShell REPL
Not used in this project's source code. JShell is a developer tool — use it to quickly test Java 21 expressions without creating a class.
1 High Level Overview

JShell is Java's first official REPL (Read-Eval-Print Loop). Run jshell from your terminal to interactively evaluate Java expressions, statements, and declarations without boilerplate. Supports tab completion, /list, /edit, /save, and /open commands. Extremely useful for learning and prototyping.

2 Examples
Interactive sessionSimple
$ jshell
jshell> int score = 78
score ==> 78

jshell> String grade = score >= 75 ? "A" : score >= 50 ? "B" : "C"
grade ==> "B"

jshell> List.of(1,2,3).stream().mapToInt(i->i).sum()
$3 ==> 6

jshell> /exit
Collection Factory Methods
Used in this project — List.of("MATHS","SCIENCE","ENGLISH") subject config, Set.of for valid grades.
1 High Level Overview

List.of(), Set.of(), Map.of(), Map.entry() create compact, immutable collections in a single expression. They throw UnsupportedOperationException on mutation, NullPointerException on null elements, and IllegalArgumentException on duplicate set/map keys. Ideal for constants and config values.

2 Examples
Immutable lists and mapsSimple
// Java 8 — mutable + extra step to make unmodifiable
List<String> old = new ArrayList<>(Arrays.asList("A","B","C"));
List<String> immutable = Collections.unmodifiableList(old);

// Java 9 — one line, truly immutable
List<String> subjects = List.of("MATHS", "SCIENCE", "ENGLISH");
Set<String> grades    = Set.of("A", "B", "C", "F");
Map<String,Integer> thresholds = Map.of("A",75, "B",50, "C",35);

subjects.add("PE");  // throws UnsupportedOperationException
Map.ofEntries for larger mapsMedium
// Map.of supports max 10 pairs; use Map.ofEntries for more
Map<String, String> errorMessages = Map.ofEntries(
    Map.entry("STUDENT_NOT_FOUND",  "Student does not exist"),
    Map.entry("MARK_NOT_FOUND",     "Mark record does not exist"),
    Map.entry("DUPLICATE_ROLL",     "Roll number already registered"),
    Map.entry("INVALID_SCORE",      "Score must be between 0 and 100"),
    Map.entry("ACCESS_DENIED",      "You do not have permission")
);

Stream API Updates — takeWhile, dropWhile, ofNullable, iterate
Used in this project — takeWhile for top results until grade drops, ofNullable for nullable filter params.
1 High Level Overview

takeWhile(predicate) takes elements while the condition is true, then stops — unlike filter which continues through all elements. dropWhile(predicate) drops elements while true, then takes the rest. Stream.ofNullable(value) produces a 0-or-1 element stream from a nullable value. Stream.iterate(seed, hasNext, next) provides a finite iterate (unlike Java 8's infinite version).

2 Examples
takeWhile and dropWhileSimple
List<Integer> scores = List.of(95, 88, 72, 61, 48, 35, 20);

// Take while >= 50 (stops at 48)
List<Integer> passing = scores.stream()
    .takeWhile(s -> s >= 50)
    .collect(Collectors.toList());
// [95, 88, 72, 61]

// Drop while >= 50 (keeps from 48 onwards)
List<Integer> failing = scores.stream()
    .dropWhile(s -> s >= 50)
    .collect(Collectors.toList());
// [48, 35, 20]
Stream.ofNullable + iterateMedium
// ofNullable — bridge nullable param into stream
String filter = getNameFilter();  // might be null
Stream.ofNullable(filter)
    .flatMap(f -> repo.findByNameContaining(f).stream())
    .map(this::toDTO)
    .forEach(results::add);

// iterate with hasNext (Java 9) — finite sequence
Stream.iterate(1, n -> n <= 100, n -> n + 1)
    .filter(n -> n % 3 == 0)
    .forEach(System.out::println); // 3,6,9...99

Optional Updates — or(), ifPresentOrElse(), stream()
Used in this project — or() for fallback lookup by roll number then email.
1 High Level Overview

Optional.or(Supplier<Optional>) returns this Optional if present, else calls the supplier for a fallback Optional — enabling Optional chaining. ifPresentOrElse(consumer, runnable) handles both cases inline. Optional.stream() converts to a 0-or-1 Stream, useful for flatMap in stream pipelines.

2 Examples
or() chainingSimple
// Find by primary key, fall back to username, fall back to email
Optional<User> user = userRepo.findById(id)
    .or(() -> userRepo.findByUsername(username))
    .or(() -> userRepo.findByEmail(email));

user.ifPresentOrElse(
    u -> log.info("Found: {}", u.getUsername()),
    () -> log.warn("User not found for any identifier")
);
Optional.stream() in pipelineMedium
// Flatten a list of Optionals into present values
List<Optional<StudentDTO>> maybes = ids.stream()
    .map(id -> studentRepo.findById(id).map(this::toDTO))
    .collect(Collectors.toList());

List<StudentDTO> found = maybes.stream()
    .flatMap(Optional::stream)  // Java 9 — drop empties
    .collect(Collectors.toList());

Private Interface Methods
Used in this project — shared validation logic inside validator interfaces.
1 High Level Overview

Interfaces can now have private and private static methods to share implementation between default methods without exposing that logic as part of the contract. Prevents code duplication inside interfaces that have multiple related default methods.

2 Examples
Shared logic via private methodSimple
interface Validator<T> {
    boolean isValid(T value);

    default boolean isValidAndNotNull(T value) {
        return value != null && isValid(value);  // calls private helper
    }
    default String validationMessage(T value) {
        return isValidAndNotNull(value) ? "OK" : buildMessage(value);
    }

    private String buildMessage(T value) {   // private — shared, not exposed
        return "Validation failed for: " + value;
    }
}
3 In This Project
validation/ResultValidator.java (interface concept)
public interface ResultValidator {
    default boolean isValidMark(int score) {
        return isInRange(score);
    }
    default boolean isValidGrade(String grade) {
        return grade != null && isKnownGrade(grade);
    }
    private boolean isInRange(int score) {   // private shared helper
        return score >= 0 && score <= 100;
    }
    private boolean isKnownGrade(String grade) {
        return Set.of("A","B","C","F").contains(grade);
    }
}
Multi-Release JARs
Not used in this project. Multi-Release JARs are for library authors who want to ship one JAR that uses newer APIs when available, falling back to older implementations on older JVMs.
1 High Level Overview

A Multi-Release JAR (MR-JAR) contains version-specific class files under META-INF/versions/N/. When running on Java N or later, the JVM uses those classes instead of the root ones. This allows a library to use Java 11 HttpClient when available, falling back to Java 8 HttpURLConnection on older JVMs — all in one JAR.

2 Examples
MR-JAR structureSimple
// JAR structure:
// com/example/HttpHelper.class         <-- Java 8 implementation
// META-INF/versions/11/
//   com/example/HttpHelper.class       <-- Java 11 implementation (HttpClient)
// META-INF/MANIFEST.MF:
//   Multi-Release: true

// Java 8 JVM uses root HttpHelper (URLConnection)
// Java 11+ JVM uses META-INF/versions/11/ HttpHelper (HttpClient)
