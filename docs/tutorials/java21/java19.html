Virtual Threads JEP 425 — Preview → Standard in Java 21
Used in this project — spring.threads.virtual.enabled=true enables virtual threads for all HTTP request handling. Standard in Java 21.
1 High Level Overview

Virtual threads (Project Loom) are lightweight threads managed by the JVM, not the OS. A platform thread costs ~1MB stack. A virtual thread costs ~a few KB. You can run millions of virtual threads concurrently. They are designed for blocking I/O — when a virtual thread blocks (JDBC, HTTP, file), the JVM parks it and frees the carrier platform thread for other work. Result: write simple blocking code, get async scalability.

2 Examples
Create virtual threadsSimple
// Platform thread — limited to ~thousands
Thread t1 = new Thread(() -> doWork());
t1.start();

// Virtual thread — Java 21 API (preview in Java 19)
Thread vt = Thread.ofVirtual().start(() -> doWork());

// Virtual thread per task executor
try (var executor = Executors.newVirtualThreadPerTaskExecutor()) {
    for (int i = 0; i < 1_000_000; i++) {
        executor.submit(() -> doWork());  // 1 million virtual threads!
    }
} // waits for all to complete
Virtual threads vs platform threadsMedium
// Platform threads — 200 max (Tomcat default)
// When all 200 are blocked on DB, new requests queue up
ExecutorService pool = Executors.newFixedThreadPool(200);

// Virtual threads — 10,000 concurrent requests, each blocks on DB
// JVM parks blocked ones, uses ~8 carrier threads efficiently
ExecutorService vPool = Executors.newVirtualThreadPerTaskExecutor();

// Benchmark: HTTP server handling 10k concurrent requests
// Platform: ~200 req/sec (bottlenecked by thread pool)
// Virtual:  ~8,000 req/sec (I/O overlap, no queue)
Spring Boot + virtual threadsReal-time
// application.yml — enables virtual threads for Tomcat + @Async
spring:
  threads:
    virtual:
      enabled: true

// Effect: every HTTP request runs on a virtual thread
// JDBC calls, Redis calls, Mail calls — all blocking, all free
// No reactive/callback code needed

Structured Concurrency JEP 428 — Incubator → Preview in Java 21
Used in this project — fetch marks for all 3 subjects in parallel; if any fails, all are cancelled.
1 High Level Overview

Structured concurrency treats a group of concurrent tasks as a single unit with a clear lifecycle. Tasks forked within a StructuredTaskScope are children of that scope. When the scope closes, all children complete or are cancelled. ShutdownOnFailure cancels all children if any fails. ShutdownOnSuccess cancels all children when any succeeds first. Prevents thread leaks and simplifies error handling compared to CompletableFuture chains.

2 Examples
Fan-out with ShutdownOnFailureSimple
// Fetch user + orders in parallel; fail fast if either fails
try (var scope = new StructuredTaskScope.ShutdownOnFailure()) {
    Subtask<User>   userTask   = scope.fork(() -> userRepo.findById(userId));
    Subtask<Order[]> orderTask = scope.fork(() -> orderRepo.findByUser(userId));

    scope.join()           // wait for both
         .throwIfFailed(); // throw if either failed

    return new UserProfile(userTask.get(), orderTask.get());
}
Race — first to succeed winsMedium
// Try primary and backup DB simultaneously — use whichever responds first
try (var scope = new StructuredTaskScope.ShutdownOnSuccess<Student>()) {
    scope.fork(() -> primaryDb.findStudent(id));
    scope.fork(() -> backupDb.findStudent(id));

    scope.join();
    return scope.result();  // whichever finished first
}
3 In This Project
service/impl/ResultServiceImpl.java — parallel subject fetch
public ResultSummaryDTO getFullResults(Long studentId) throws Exception {
    try (var scope = new StructuredTaskScope.ShutdownOnFailure()) {
        var mathsFuture   = scope.fork(() ->
            markRepo.findByStudentAndSubject(studentId, "MATHS"));
        var scienceFuture = scope.fork(() ->
            markRepo.findByStudentAndSubject(studentId, "SCIENCE"));
        var englishFuture = scope.fork(() ->
            markRepo.findByStudentAndSubject(studentId, "ENGLISH"));

        scope.join().throwIfFailed();

        var allMarks = Stream.of(
            mathsFuture.get(), scienceFuture.get(), englishFuture.get()
        ).flatMap(Optional::stream).collect(Collectors.toList());

        return buildSummary(studentId, allMarks);
    }
}
Record Patterns JEP 405 — Preview → Standard in Java 21
Used in this project — destructure ServiceResult.Success(var dto) in switch. Standard in Java 21.
1 High Level Overview

Record patterns extend pattern matching to destructure record components directly in instanceof and switch. Instead of matching a record type and then calling accessors, you bind the components in one step: case Success(var dto). Patterns can be nested: case Success(StudentDTO(var id, var name, _, _)) extracts inner record components.

2 Examples
Destructure in instanceofSimple
// Without record patterns
if (result instanceof ServiceResult.Success s) {
    var dto = (StudentDTO) s.value();  // still need to call accessor + cast
    System.out.println(dto.name());
}

// With record patterns — destructure directly
if (result instanceof ServiceResult.Success(var dto)) {
    System.out.println(dto.name());  // dto already bound as StudentDTO
}
Nested record patterns in switchReal-time
// Destructure 2 levels deep in switch
return switch (studentService.getStudent(id, principal)) {
    case ServiceResult.Success(StudentDTO(var sid, var name, var roll, _)) ->
        ResponseEntity.ok(Map.of("id", sid, "name", name, "roll", roll));
    case ServiceResult.NotFound(var msg)        -> notFound(msg);
    case ServiceResult.Forbidden(var msg)       -> forbidden(msg);
    case ServiceResult.ValidationError(var msg) -> badRequest(msg);
};
// _ = unnamed pattern (Java 21) — ignores email field of StudentDTO
Foreign Function & Memory API JEP 424 — Preview
Not used in this project. Continues evolving from Java 17 incubator. Standard in Java 22.
1 High Level Overview

The Foreign Function & Memory API in Java 19 preview added Arena for memory lifetime management, MemoryLayout for describing native struct layouts, and improved Linker API for calling native functions. It's the modern, safe replacement for both JNI and sun.misc.Unsafe for off-heap operations.

2 Examples
Arena-scoped off-heap memorySimple
// Arena controls lifetime of native memory
try (Arena arena = Arena.ofConfined()) {
    // Allocate off-heap struct
    MemorySegment point = arena.allocate(8);  // 2 ints
    point.set(ValueLayout.JAVA_INT, 0, 10);   // x = 10
    point.set(ValueLayout.JAVA_INT, 4, 20);   // y = 20

    int x = point.get(ValueLayout.JAVA_INT, 0); // 10
}
// Memory automatically freed when arena closes
