Java 13 — Text Blocks & Dynamic CDS

Text Blocks entered preview in Java 13, making multi-line strings readable for the first time. They graduated to standard in Java 15.

Text Blocks JEP 355 — Preview
Used in this project — SQL query constants in repositories, email templates in scheduler. Standard in Java 15.
1 High Level Overview

Text blocks are multi-line string literals using triple-quotes """...""". The compiler strips common leading whitespace automatically (incidental indentation). No need to escape inner double-quotes, newlines, or most special characters. The closing """ position controls indentation stripping. \ at line end suppresses the newline. \s preserves trailing spaces.

2 Examples
Multi-line SQL and JSONSimple
// Old way — escape hell
String sql = "SELECT m.score, s.name\n" +
             "FROM marks m\n" +
             "JOIN subjects s ON m.subject_id = s.id\n" +
             "WHERE m.student_id = ?";

// Text block — readable
String sql = """
    SELECT m.score, s.name
    FROM marks m
    JOIN subjects s ON m.subject_id = s.id
    WHERE m.student_id = ?
    """;

// JSON text block
String json = """
    {
        "studentId": 42,
        "subject": "MATHS",
        "score": 87
    }
    """;

Text block indentation controlReal-time
// Closing """ position controls indentation
String indented = """
        line1
        line2
    """;
// Result: "    line1\n    line2\n"  (4 spaces kept)

String notIndented = """
        line1
        line2
""";
// Result: "        line1\n        line2\n"  (8 spaces kept)

// \ suppresses newline (continuation)
String oneLine = """
    SELECT * \
    FROM students \
    WHERE id = ?
    """;
// Result: "SELECT * FROM students WHERE id = ?"

Dynamic CDS Archives JEP 350
Not in application source code. JVM startup optimisation — configured via JVM flags. Spring Boot 3.3 adds built-in CDS support.
1 High Level Overview

Dynamic CDS Archives (Java 13) extends App CDS (Java 10) to allow creating a CDS archive automatically at application exit, without a separate class-list generation step. Run once with -XX:ArchiveClassesAtExit=app.jsa, then use the archive on subsequent runs with -XX:SharedArchiveFile=app.jsa. Spring Boot 3.3 automates this via spring.context.checkpoint.

2 Examples
Auto-generate archive at exitSimple
// First run — generates archive at exit
java -XX:ArchiveClassesAtExit=student.jsa -jar student.jar

// Subsequent runs — faster startup using archive
java -XX:SharedArchiveFile=student.jsa -jar student.jar

// Spring Boot 3.3 — automated
// mvn spring-boot:process-aot
// Then run normally — Spring Boot manages the archive
