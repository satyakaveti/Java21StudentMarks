Java 15 — Text Blocks Standard & Sealed Classes Preview

Text blocks became stable (no preview flag). Sealed classes entered preview, introducing controlled type hierarchies that unlock exhaustive pattern matching.

Text Blocks — Standard JEP 378
Used in this project — all SQL queries and email templates use text blocks without --enable-preview.
1 High Level Overview

Text blocks graduate from preview (Java 13–14) to standard in Java 15. No more --enable-preview flag needed. They are now a permanent part of the language. The \ line continuation and \s trailing space preservation (added in Java 14 second preview) are also standard.

Sealed Classes JEP 360 — Preview → Standard in Java 17
Used in this project — ServiceResult sealed interface with Success, NotFound, Forbidden, ValidationError subtypes.
1 High Level Overview

Sealed classes (sealed keyword + permits clause) restrict which classes can extend or implement them. Each permitted subtype must be final, sealed, or non-sealed. This creates a closed type hierarchy — the compiler knows all possible subtypes, enabling exhaustive switch expressions with no default case needed. Perfect for result types, AST nodes, and event hierarchies.

2 Examples
Basic sealed hierarchySimple
// Sealed interface — only these 3 can implement it
sealed interface Shape permits Circle, Rectangle, Triangle {}

final class Circle    implements Shape { double radius; }
final class Rectangle implements Shape { double width, height; }
final class Triangle  implements Shape { double base, height; }

// Compiler enforces exhaustiveness in switch
double area = switch (shape) {
    case Circle c    -> Math.PI * c.radius * c.radius;
    case Rectangle r -> r.width * r.height;
    case Triangle t  -> 0.5 * t.base * t.height;
    // No default needed — all cases covered!
};
Sealed + Records for result typeMedium
// Sealed interface with record subtypes
sealed interface ServiceResult<T>
    permits ServiceResult.Success, ServiceResult.NotFound,
            ServiceResult.Forbidden, ServiceResult.ValidationError {

    record Success<T>(T value)            implements ServiceResult<T> {}
    record NotFound<T>(String message)    implements ServiceResult<T> {}
    record Forbidden<T>(String message)   implements ServiceResult<T> {}
    record ValidationError<T>(String msg) implements ServiceResult<T> {}
}

// Exhaustive switch — no default
return switch (result) {
    case ServiceResult.Success(var v)         -> ResponseEntity.ok(v);
    case ServiceResult.NotFound(var msg)      -> ResponseEntity.notFound().build();
    case ServiceResult.Forbidden(var msg)     -> ResponseEntity.status(403).build();
    case ServiceResult.ValidationError(var m) -> ResponseEntity.badRequest().build();
};

public sealed interface ServiceResult<T>
    permits ServiceResult.Success, ServiceResult.NotFound,
            ServiceResult.Forbidden, ServiceResult.ValidationError {

    record Success<T>(T value)            implements ServiceResult<T> {}
    record NotFound<T>(String message)    implements ServiceResult<T> {}
    record Forbidden<T>(String message)   implements ServiceResult<T> {}
    record ValidationError<T>(String msg) implements ServiceResult<T> {}

    static <T> ServiceResult<T> success(T value)         { return new Success<>(value); }
    static <T> ServiceResult<T> notFound(String msg)     { return new NotFound<>(msg); }
    static <T> ServiceResult<T> forbidden(String msg)    { return new Forbidden<>(msg); }
    static <T> ServiceResult<T> validationError(String m){ return new ValidationError<>(m); }
}
Hidden Classes JEP 371
Not used in application code. Used internally by frameworks like Spring (proxy generation) and lambda implementations.
1 High Level Overview

Hidden classes are classes that cannot be used directly by bytecode of other classes and are intended for use by frameworks that generate classes at runtime. They replace unsafe use of Unsafe.defineAnonymousClass(). Hidden classes are not discoverable, can be unloaded independently of their classloader, and are used by Spring's CGLIB proxy generation and the JVM's lambda implementation.

2 Examples
Define a hidden class (framework use)Simple
// Framework code — not application code
byte[] classBytes = generateProxyBytecode();  // generate via ASM or similar

Lookup lookup = MethodHandles.lookup();
Lookup hiddenLookup = lookup.defineHiddenClass(
    classBytes,
    true,  // initialize immediately
    MethodHandles.Lookup.ClassOption.NESTMATE
);

Class<?> hiddenClass = hiddenLookup.lookupClass();
// Cannot be referenced by name — only via the Lookup
// Used by Spring CGLIB, Hibernate proxy generation, lambdas
ZGC — Production Ready
ZGC was experimental in Java 11–14, production-ready in Java 15. This project uses Generational ZGC (Java 21) which is an evolution of this.
1 High Level Overview

ZGC (Z Garbage Collector) became production-ready in Java 15 (JEP 377). It provides sub-millisecond GC pauses, performs all expensive work concurrently, and scales from MB to TB heaps. In Java 21, Generational ZGC added young/old generation collection, making it significantly more throughput-efficient for typical server applications.
