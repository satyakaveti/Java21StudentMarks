Java 18 — UTF-8 Default, Simple Web Server & JavaDoc Snippets

A smaller release focused on quality of life improvements. UTF-8 became the default charset, eliminating a long-standing source of encoding bugs across platforms.

UTF-8 by Default JEP 400
Benefits this project — student names with Unicode characters (Telugu, Hindi, etc.) are handled correctly without explicit charset specification.
1 High Level Overview

Before Java 18, the default charset was platform-dependent — UTF-8 on Linux/macOS, Windows-1252 on Windows. This caused file I/O, stream reading, and string conversion bugs when code ran on different OSes. Java 18 standardized UTF-8 as the default for all Java APIs regardless of platform. APIs that use Charset.defaultCharset() now always return UTF-8.

2 Examples
Before vs after Java 18Simple
// Before Java 18 — explicit charset required for cross-platform safety
Files.writeString(Path.of("names.txt"), "Satya కవేటి", StandardCharsets.UTF_8);
String content = Files.readString(Path.of("names.txt"), StandardCharsets.UTF_8);

// Java 18+ — UTF-8 is the default
Files.writeString(Path.of("names.txt"), "Satya కవేటి"); // UTF-8 by default
String content = Files.readString(Path.of("names.txt")); // UTF-8 by default

// Check default charset
Charset.defaultCharset(); // always UTF-8 in Java 18+
Impact on CSV importMedium
// Java 17 on Windows — might read garbled Unicode names
BufferedReader reader = new BufferedReader(new FileReader("students.csv"));

// Java 18+ — same code, UTF-8 on all platforms
BufferedReader reader = new BufferedReader(new FileReader("students.csv"));
// "Priya Müller" reads correctly on Windows, Linux, macOS

// For safety, still explicit is best practice:
BufferedReader reader = new BufferedReader(
    new InputStreamReader(new FileInputStream("students.csv"), StandardCharsets.UTF_8));

# application.yml — explicit UTF-8 for file resources (belt and suspenders)

  mandatory-file-encoding: UTF-8  # fails fast if JVM default is not UTF-8

Simple Web Server JEP 408
Not used in this project. The project uses Spring Boot's embedded Tomcat. The Simple Web Server is a dev tool for serving static files.
1 High Level Overview

Java 18 ships a minimal HTTP file server usable from the command line: jwebserver. Serves static files from the current directory on port 8000. Useful for quick demos, serving HTML/CSS during development, or testing HTTP clients without a full web framework. Not suitable for production use — no SSL, no routing, no dynamic content.

2 Examples
Command line usageSimple
// Serve current directory on port 8000
$ jwebserver
Serving /Users/satyakaveti/Code/Workspace/Own/Java21StudentMarks
URL http://127.0.0.1:8000/

// Custom port and directory
$ jwebserver -p 9090 -d /path/to/docs

// Now you can access:
// http://localhost:9090/docs/tutorials/index.html
Programmatic usageMedium
// Create a simple file server programmatically
var server = SimpleFileServer.createFileServer(
    new InetSocketAddress(8080),
    Path.of("/docs"),
    SimpleFileServer.OutputLevel.VERBOSE
);
server.start();
// Serves /docs at http://localhost:8080
// No Spring, no dependencies
JavaDoc Code Snippets JEP 413
Not in application source code. Used in library/API documentation. The @snippet tag enables validated, highlighted code examples in Javadoc.
1 High Level Overview

Java 18 introduced the {@snippet ...} Javadoc tag to replace the <pre>{@code ...}</pre> pattern. Snippets can reference external files (validated at compile time), include region markers, and have syntax highlighting in generated docs. This ensures code examples in docs stay in sync with actual source.

2 Examples
Inline and file-based snippetsSimple
/**
 * Returns the grade for a given score.
 *
 * {@snippet :
 *   int score = 87;
 *   String grade = resultService.gradeFor(score); // grade == "B"
 * }
 *
 * External file snippet (validated at compile time):
 * {@snippet file="GradeExample.java" region="gradeCalc"}
 */
public String gradeFor(int score) { ... }
