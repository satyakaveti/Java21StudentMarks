Java 17 LTS — Sealed Classes Standard & Strong Encapsulation

The second LTS since Java 11 and the minimum baseline for Spring Boot 3.x. Sealed classes finalized. JDK internals strongly encapsulated — no more --add-opens hacks.

Sealed Classes — Standard JEP 409
Used in this project — ServiceResult sealed interface is standard Java 17+ — no preview flag needed.
1 High Level Overview

Sealed classes graduate from preview (Java 15–16) to standard in Java 17. Combined with records (standard since Java 16) and pattern matching in switch (Java 21), sealed classes enable a complete algebraic data type system in Java. Spring Boot 3.x requires Java 17+ and takes advantage of sealed types for configuration and result modelling.

2 Examples
Sealed + records — complete ADTSimple
// Algebraic data type — closed set of variants
sealed interface ApiResponse<T>
    permits ApiResponse.Ok, ApiResponse.Err, ApiResponse.Loading {}

record Ok<T>(T data)            implements ApiResponse<T> {}
record Err<T>(String message)   implements ApiResponse<T> {}
record Loading<T>()             implements ApiResponse<T> {}

// Exhaustive switch — compiler verifies all cases
String render(ApiResponse<Student> r) {
    return switch (r) {
        case Ok(var s)      -> "Student: " + s.getName();
        case Err(var msg)   -> "Error: " + msg;
        case Loading()      -> "Loading...";
    };
}
Nested sealed hierarchyMedium
sealed interface AuditEvent permits AuditEvent.Create, AuditEvent.Update, AuditEvent.Delete {}

record Create(Long entityId, String entityType, Object newValue)
    implements AuditEvent {}
record Update(Long entityId, String entityType, Object oldValue, Object newValue)
    implements AuditEvent {}
record Delete(Long entityId, String entityType)
    implements AuditEvent {}

// In AuditAspect
void recordEvent(AuditEvent event) {
    String desc = switch (event) {
        case Create(var id, var type, var val) ->
            "Created %s(%d): %s".formatted(type, id, val);
        case Update(var id, var type, var old, var nw) ->
            "Updated %s(%d): %s → %s".formatted(type, id, old, nw);
        case Delete(var id, var type) ->
            "Deleted %s(%d)".formatted(type, id);
    };
    auditRepository.save(new AuditLog(desc, LocalDateTime.now()));
}

dto/ServiceResult.java — sealed + records, both standard in Java 17
// Standard Java 17 — no --enable-preview
public sealed interface ServiceResult<T>
    permits ServiceResult.Success, ServiceResult.NotFound,
            ServiceResult.Forbidden, ServiceResult.ValidationError {

    record Success<T>(T value)            implements ServiceResult<T> {}
    record NotFound<T>(String message)    implements ServiceResult<T> {}
    record Forbidden<T>(String message)   implements ServiceResult<T> {}
    record ValidationError<T>(String msg) implements ServiceResult<T> {}
}

// Used in every service method
public ServiceResult<StudentDTO> getStudent(Long id) {
    return studentRepository.findById(id)
        .filter(s -> !s.isDeleted())
        .map(s -> ServiceResult.<StudentDTO>success(toDTO(s)))
        .orElse(ServiceResult.notFound("Student " + id + " not found"));
}
Strong Encapsulation of JDK Internals JEP 403
Benefits this project — eliminates InaccessibleObjectException surprises. No --add-opens hacks needed in Spring Boot 3.x which is designed for Java 17.
1 High Level Overview

Java 17 fully enforces encapsulation of JDK internal APIs. Packages like sun.misc, sun.reflect, and com.sun.* are no longer accessible via reflection without explicit --add-opens flags. This forces libraries to use official APIs. Spring Boot 3.x was built from the ground up for Java 17, so it doesn't need any --add-opens flags.

Strong encapsulation in practiceSimple

Pattern Matching Enhancements (Groundwork)
Java 17 laid the groundwork for pattern matching in switch (Java 21). The sealed + records combination is the foundation used in this project's ServiceResult dispatch.
1 High Level Overview

Java 17 did not add new pattern matching features per se, but the combination of finalized sealed classes + records + instanceof pattern matching created a complete foundation. Java 18–21 built the switch pattern matching on top. If you're on Java 17, you can use instanceof patterns extensively; full switch patterns require Java 21.

3 In This Project
Progression from Java 17 to Java 21 in this project
// Java 17 — instanceof patterns only
if (result instanceof ServiceResult.Success<StudentDTO> s) {
    return ResponseEntity.ok(s.value());
} else if (result instanceof ServiceResult.NotFound<StudentDTO> n) {
    return ResponseEntity.notFound().build();
}

// Java 21 — full pattern matching in switch (used in this project)
return switch (result) {
    case ServiceResult.Success(var dto)         -> ResponseEntity.ok(dto);
    case ServiceResult.NotFound(var msg)        -> ResponseEntity.notFound().build();
    case ServiceResult.Forbidden(var msg)       -> ResponseEntity.status(403).build();
    case ServiceResult.ValidationError(var msg) -> ResponseEntity.badRequest().build();
    // Compiler verifies all 4 sealed subtypes covered
};
Foreign Function & Memory API JEP 412 — Incubator
Not used in this project. FFM API is for calling native code (C/C++) from Java without JNI. Standard in Java 22.
1 High Level Overview

The Foreign Function & Memory API (Project Panama) allows Java programs to call native libraries and access off-heap memory without JNI boilerplate. It provides MemorySegment (safe off-heap memory), MethodHandle-based native calls, and Arena-scoped memory lifetimes. Much safer than Unsafe and simpler than JNI. Standard in Java 22 (JEP 454).

2 Examples
Call native C function (Java 22 API)Simple
// Call C strlen() from Java — no JNI needed
try (Arena arena = Arena.ofConfined()) {
    Linker linker = Linker.nativeLinker();
    SymbolLookup stdlib = linker.defaultLookup();

    MethodHandle strlen = linker.downcallHandle(
        stdlib.find("strlen").get(),
        FunctionDescriptor.of(JAVA_LONG, ADDRESS)
    );

    MemorySegment str = arena.allocateUtf8String("hello");
    long len = (long) strlen.invoke(str);  // 5
}
